# ★HTMLファイルの基本構造［p.003］

## 【DOCTYPE［１行目］とhtml要素［２行目以降］】

HTMLファイルは＜html＞という記述から始まる。

html要素ではなく、「DOCTYPE（文書型）宣言」と呼ばれる要素である。

通常、DOCTYPE宣言を記述しなくてもWebページは表示されるが、宣言が無い場合、ブラウザは「互換モード」でHTMLを解釈するため、CSSやJavaScriptの表示や挙動が異なる場合がある。

→互換モード：ブラウザが過去に定めていた独自ルール

◎DOCTYPE宣言の記述は義務である

DOCTYPE宣言にhtml（＜html＞）が続く。

HTMLドキュメントの下にその終了タグ（＜/html＞）がある。

> ［メモ］
html要素内で指定されることの多いlang属性（［例］＜html lang=”ja”＞）は、Googleでは無視しているという話があるが、自動翻訳のミスなどを避けるために付けておくとよい。
DOCTYPE宣言を除く、すべての要素がこのhtml要素の子孫要素（入れ子の構造）となる。
html要素の構成は「head要素」と「body」要素の２つに分けられる
> 

# ★head要素とは

head要素のコンテント（子要素）は、Webページに関する付加情報であり、原則としてブラウザには表示されない。

［代表的な要素］

- meta 要素　…　Webページに対するメタ情報［p.003］を指定する。
    
    ［例］＜meta charset =”UTF-8” ／＞：文字コードの指定
    
    HTMLファイルの文字コードに合わせてきちんと指定しないと文字化けする時代があったが、現在では「UTF-8」を指定しておけば、ほぼ大丈夫な状況である。
    
- title 要素　…　Webページのタイトル［p.004］。head要素の子要素の中でもこの要素だけはブラウザのタブなどに表示される。

# ★body要素とは

body要素には、ブラウザに表示される内容を記述していく。

一般に、文書（ドキュメント）は「見出し」「段落」「リスト」「画像」「表」で構成される。
HTMLは文書を記述するための技術として用意されたので、これらの構成部品をマークアップする要素が用意されている。

また、ハイパーテキストなので、「リンク」の要素も用意されている。
加えて、Webページからサーバーに情報（データ）を送ることのできる、「フォーム」の要素（入力フォームやボタンなど）がある。

→Webアプリ開発ではそのフォームの要素が主役となる。

その他、ドキュメントをより正確に構造化するための要素や、CSSでスタイリングするために使用される要素などがある。

# 【HTMLの基本文法】

## 【「タグ」と「属性」】

＜＞で囲われた文字列（＜html＞＜head＞など）を「タグ」という。HTMLではタグを使ってドキュメントを構造化する。

コンピュータ（ブラウザ）は、タグで構造化されたHTMLファイルを読み込んで、人間が読みやすいように整形して表示する

### A. タグとは

```html
<タグ名> コンテント </タグ名>
開始タグ　　内容　　　終了タグ（開始タグの先頭にスラッシュを含めたタグ）
<----------要素------------>
			（エレメント）
```

※終了タグの存在しないhtml要素（空要素）もある（meta要素、br要素）など。

→　空要素にはコンテントに当たるぶぶんがないので、終了タグは不要になる。

なお、空要素には＜meta ／＞のように閉じ括弧を「／＞」とする記述もある。

### ［補足］

Q. 空要素の末尾にスラッシュを付ける？つけない？

A. 開発分野やツールの仕様の有無によって使い分けられている。

#### ★フロントエンド：開発状況に依るが、「つけない派」が多い傾向にある。

素のHTML作成では、web標準（HTML Living Standard）の仕様に準拠する動きが強まっており、スラッシュを付けないスタイルが指示を集めている。

それに伴い、コードを自動整形するツールも以前はスラッシュを自動挿入していたが、現在は削除する仕様に変更され、普及する要因となっている。

一方、フレームワーク開発では構文の制限からスラッシュを付ける必要がある。そのため、素のHTML作成でも無意識に付ける場合が多い。

→フレームワーク：プログラム全体の枠組みを提供するツール

#### ★バックエンド：開発状況に依るが「つける派」が多い傾向にある。

フレームワーク開発する場合が多いため、スラッシュを付ける必要がある。

また他のシステムとのデータの受け渡しを考慮する場合、安全性のためにスラッシュを義務付けられている場合がある。

#### ★共通：（バックエンド・フロントエンド問わず）

中高年のベテランエンジニアや、歴史の長いWebサイト・アプリの運用保守を行っている現場では、当時の記述習慣がエンジニアの共通認識として深く定着しており、その名残が現代のシステムや規約にも引き継がれている。

### B. 属性とは

［例］

```html
<meta charset ="UTF-8" />
				属性名　属性値
				<----属性---->
```
