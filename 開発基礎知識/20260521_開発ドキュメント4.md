# 単体テスト
クラスを単位で動かして、その内部ロジックを検証するテスト。単純な文法ミスはプログラム作成段階で解決済みとする。

1. 静的テスト
    プログラムを実行せずに、プログラムの分析を机上で行うことによって確認する
    
2. 動的テスト
    実際にテストデータを与えてプログラムを実行し、正しく処理・動作することを確認する

---

# 静的テスト

## レビュー

複数人で討議することにより、エラーなどを発見する

- ウォークスルー
    
    開発者が主体となって、参加者全員がプログラムを目で追いかけながらエラーを調べる形態
    
- インスペクション
    
    事前に役割を決められた参加者が、責任のある第三者の下でエラーなどを調べる形態
    

## リバースエンジニアリング

# 動的テスト

## ホワイトボックステスト

プログラムの内部構造をしって、分岐や繰り返しの命令が正しく動くかをテストする方法

- **網羅率**
    
    全ての経路に対するテストで実行した経路の割合
    
    - プログラムには多くの分岐や繰り返しがある。それらのケースを隈なくテストすることが求められる
    - 網羅基準の分類
        - 命令網羅
        - 判定条件網羅
        - 条件網羅
        - 複数条件網羅
- 命令網羅
    
    全ての処理（命令）を最低一回は通すようにするテスト
    
- 判定条件網羅
    
    すべての分岐を最低１回は通すようにするテスト
    
- 条件網羅
    
    個々の条件を最低１回は満たすようにするテスト
    
- 複数条件網羅
    
    想定される条件の組み合わせをすべて網羅するテスト
    

## ブラックボックステスト

- プログラムの内部構造を考慮せず、外部仕様書に基づいたさまざまな入力データを与えて、仕様書どおりの出力が得られるかどうかを確認する方法
- ホワイトボックスではプログラマが内部仕様書を理解して正しく作られているかどうかはテスト出来る一方で、プログラマが外部仕様書を正しく理解しているかの確認はできない。そこで、設計者の意図した機能の実現をブラックボックステストで確認する。
- テストデータはPGではなく、外部仕様書作成者あるいは利用者が作成すべきである
- わざと誤りのデータを与えて、誤りであることを正しく認識されることを確かめる必要がある。プログラムに入力された誤りのデータを発見するには多大な手間を要するため、入力時点で誤りを防ぐことが重要になる。
- ブラックボックステストでは、プログラムの中を見ないため、PGが**特殊な状況の時だけに動く不正なプログラムを忍ばせていても、それを発見することはできない。**

### 同値分割法

- データ範囲を種類ごとのグループに分け、それぞれ代表的な値を選択し、テストする技法
- その選択した値が、正しくグループ分けできるかどうかを検証するテスト

### 境界値分析

- 仕様条件の境界となる前後の値に対してテストする技法
- グループ分けに応じて、テストデータは変わる

### デシジョンテーブル

想定されるすべての条件と、それに対して実行すべき動作を整理した表

- 表で使用される英字
    - 条件を満たす場合：Y、満たさない場合：N
    - 動作が発生する場合：X、発生しない場合：‐
        
        
        | 条件/アクション | ルール1 | ルール2 | ルール3 |
        | --- | --- | --- | --- |
        | 条件A | Y | Y | N |
        | 条件B | Y | N | N |
        | 期待値1 | X | - | - |
        | 期待値2 | - | X | - |
        | 期待値3 | - | - | X |

### 状態遷移

設計仕様通りのイベントによって、ソフトウェアの状態が変化することを検証するテスト

- イベント：ある状態が異なる状態に変化するきっかけ
    - 種類
        - 状態遷移図
            
            システムの状態とその変化を表した図
            
            →状態遷移全体の流れを視覚的にとらえることができる
            
            ```mermaid
            stateDiagram-v2
                [*] --> ログアウト中
                ログアウト中 --> ログイン中 : ID/パスワード入力
                ログイン中 --> ログアウト中 : ログアウトボタン押下
                ログイン中 --> エラー画面 : タイムアウト発生
                エラー画面 --> ログアウト中 : 再読み込み
            ```
            
        - 状態遷移表
            
            遷移前、遷移後の状態とイベントをまとめた表
            
            縦：遷移前、横：イベントを表記し、それぞれの組み合わせを「遷移後の状態」として表す。
            
            ■メリット
            
            - 全ての状態とイベントの組み合わせを網羅でき、想定しないイベントの対処を確認することができる
            - 遷移が発生しない「状態」と「イベント」の組み合わせを把握することができる
            
            
            | **現在の状態（遷移前）** | **イベント** | **次の状態（遷移後）** | **備考** |
            | --- | --- | --- | --- |
            | **ログアウト中** | ID/パス入力 | **ログイン中** | 認証成功時 |
            | **ログアウト中** | ID/パス入力 | **ログアウト中** | 認証失敗時 |
            | **ログイン中** | ログアウトボタン押下 | **ログアウト中** | - |
            | **ログイン中** | タイムアウト発生 | **エラー画面** | - |
            | **エラー画面** | 再読み込み | **ログアウト中** | - |

## 結合テスト

- 単体のプログラムはただしくても、複数のプログラム間でデータの受け渡しなどで誤りがないかをテストする。特に、異なるプログラマが作成したプログラムでは、思い違いが発生する危険がある。
- 結合テストの段階で、すべてのモジュールが完成している保証はない
- その場合は「スタブ」と「ドライバ」という仮の代役でテストを実施することになる

［イメージ］

舞台のリハーサルで一部の俳優がまだ来ていないときに、代役がセリフを読んで場をつなぐような状況

```java
【構造】
   親モジュール (呼び出す側)
       ↓
   子モジュール (呼び出される側)

【テスト中の状況】
[Case A：親だけ完成している場合]
   親モジュール
       ↓
   [スタブ (子役の代わり)]  ← 子が未完成なのでスタブで代用！

[Case B：子だけ完成している場合]
   [ドライバ (親役の代わり)]  ← 親が未完成なのでドライバで代用！
       ↓
   子モジュール
```

### トップダウンテスト

- 上位モジュール（親の役割）から順にテストしていく方式
- 下位モジュールが未完成でも、上位からの流れをテストできるように、「スタブ」を使って下位をごまかす。
- スタブはまだ完成していない下位モジュールの代わりである
    - 下位モジュールの本当の処理は出来ないが、ダミー値を返すだけの簡単な代役である
    
    ```java
    // 本物の代わり（インターフェースやメソッド名を揃える）
    class Stub {
        public int getResult() {
            return 100; // とりあえず決まった値を返すだけ
        }
    }
    
    // 親プログラム（完成済み）
    // 本物の代わりにStubを呼び出す
    int data = new Stub().getResult();
    ```
    

### ボトムアップテスト

- 下位モジュールから順にテストしていく方式
- 上位モジュールが未完成でも、下位からの流れをテストできるように、「ドライバ」を使って下位をごまかす。
- ドライバはまだ完成していない上位モジュールの代わりである
    - テスト対象の下位モジュールを直接呼び出して、引数を与えたり、戻り値をチェックしたりする役目である。
    
    ```java
    // テスト対象：計算機能（完成済み）
    class Calculator {
        public int add(int a, int b) { return a + b; }
    }
    
    // 【ドライバ】：親の代わりに動かすテスト用コード
    public class Driver {
        public static void main(String[] args) {
            Calculator calc = new Calculator();
            // 直接呼び出してテストデータを渡す
            System.out.println(calc.add(2, 3)); // 期待値5が出れば成功
        }
    }
    ```
