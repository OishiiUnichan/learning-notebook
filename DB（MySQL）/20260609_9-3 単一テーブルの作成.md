# 9-3 単一テーブルの作成

subject: DB
day: 2026年6月9日

単一テーブル

→他のテーブルとの連携を考慮しない

【設計のポイント】

★基本項目

1. テーブル名：管理する情報が分かる名前にする。
    
    ※他アプリからの仕様も視野に半角英数を採用する。
    
2. カラム名：格納するデータの内容が分かる名前にする。
    
    ※テーブル名と同様、半角英数を採用する。
    
3. データ型：カラム名に該当するデータが格納されていることが保証されるようにデータの種類（型）を決める。
    
    ※数値の桁数や文字数についても「大は小を兼ねる」ではなく、保存されているデータが保証されるように検討して決める。
    

☆臨時項目：制約の設定

1. 主キー（=b+c）
    
    レコードを一意に特定するための値が格納されているカラムに設定する。
    
    →他のレコードと重複する値の格納が禁止される
    
    併用可）オートインクリメント昨日：自動連番機能
    
    INSERT文で入力値を指定しなくても数値が自動的に格納される（開始の数値：１）
    
2. ユニークキー（UNIQUE制約）
    
    他のレコードと重複する値の格納が禁止される。
    
    主キーとの違い
    
    - 主キー：NULL禁止
    - ユニークキー：NULL許容
3. NOT NULL制約
    
    NULL禁止。値の入力を必須にしたいカラムに設定する。
    
    併用可）デフォルト値（規定値）
    
    INSERT文で入力値が指定されなかった場合に使用される値を設定できる。
    
4. 外部キー［p.235 9-4節］

主キーの設定方法

主キーには自動的にインデックスが設定される。インデックスとは書籍の索引のような機能に相当する。

主キーは「ユニーク制約の高速な検証」と「検索や結合の高速化」を同時に実現するために、インデックスが暗黙的に設定される仕様になってる。
