# 9-4 他テーブルと連携する

subject: DB
day: 2026年6月9日

テーブル同士は物理的に分かれているため、連携するためにはWHERE句やJOIN句で結合条件を指定する必要がある。その際、結合を保証させるために参照元と参照先のカラムに制約を加えることができる。その制約を**外部キー**という。

## 【外部キー制約】

論理的な結合が保証されるために、テーブル同士の連携が切れる操作は禁止される。

|  | データを登録する側 | データ提供する側 |
| --- | --- | --- |
| 参照元テーブル | 追加更新の制限 | 削除更新の制限 |
| 参照先テーブル | 存在しない値を登録できない | 紐づけされてるデータは**原則、** 削除や主キーの変更ができない |

※テキストの場合、参照元（子）は出庫テーブル

　　　　　　　参照先（親）は在庫テーブル

【参照アクション】

※制約の内容は参照アクションで設定できる

参照元の挙動について

|  | 参照先 |  |
| --- | --- | --- |
|  | UPDATE | DELETE |
| RESTRICT/NO ACTION（規定） | 参照先の変更を拒否 | 参照先の削除を拒否 |
| CASCADE | 参照先の変更に追従 | 参照先の削除と同時に削除 |
| SET NULL | NULLに置換 | NULLに置換 |

［phpmyadmin補足］p.237-240

②２～４列目を定義する

外部キーの設定方法

外部キーも主キーと同様に、自動的にインデックスが設定される。

外部キーは「データの整合性の確認処理」と「テーブル結合の高速化」を同時に実現するために、インデックスが暗黙的に設定される仕様になってる。

［コマンドライン］p.241 リスト9-3

新規作成

```sql
CREATE TABLE テーブル名（
カラム名 データ型 オプション,
~~~,
全体向けのオプション　［例］PRIMARY KEY（対象カラム名リスト）
													INDEX（対象カラム名リスト）
);
```

既存変更

外部キー

```sql
ALTER TABLE テーブル名
	ADD FOREIGN KEY (参照元カラム名)
	REFERENCES 参照先テーブル名(参照元カラム名) 参照アクション;
```

カラム追加

```sql
ALTER TABLE テーブル名 ADD カラム名 データ型;
```

カラム削除

```sql
ALTER TABLE テーブル名 DROP COLUMN カラム名;
```

## 【削除】

コラム

テーブル、DB削除するにはDELETEではなくDROP

［構文］

テーブル削除

```sql
DROP TABLE テーブル名;
```

DB削除

```sql
DROP DATABASE データベース名;
```

### 【補足】

全レコード（DBの中身）削除するには２つの方法がある

```sql
DELETE FROM テーブル名;　　　　［データ操作言語］
TRUNCATE TABLE テーブル名;　　　［データ定義言語］
```

TRUNCATE…DELETE文よりも高速に全レコードを削除できる。

注意

1. 素早く全レコードを削除することが目的であるため、WHERE句による条件指定は出来ない
2. データ定義言語に属するため、トランザクション処理の対象外。実行前の状態に戻すことは出来ない
