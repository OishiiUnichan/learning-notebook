# 1-2　リレーショナルデータベース（RDB）の基本

subject: DB
day: 2026年6月2日

## 🔷 リレーショナルデータベースとは

> 行と列のある表（テーブル）の形式で管理
> 

テーブル同士を結び付けてデータを管理する。
※ リレーショナルについては第8章で詳しく解説

**【例】テーブル構成**

- ① 取引先テーブル
- ② 注文発注テーブル
- ③ 商品管理テーブル
→ 上記のテーブルを用途に応じて結び付けて情報を管理する。

**【例】用途に応じたテーブルの結び付け**

- 発注商品の詳細を知りたい → テーブル②と③を関連付けたテーブルを作成
- 商品の発注先の詳細を知りたい → テーブル①と②を関連付けたテーブルを作成

---

## 🔷 管理の考え方（× と 〇）

❌ **引き算の管理（NG）**  
すべての情報を一括管理した巨大なテーブル1つで管理するのではなく  
　　→ 不要な列を非表示にする  

✅ **足し算の管理（OK）**  
あるまとまった情報ごとにテーブルを作成・管理し、用途に応じて関連のあるテーブルを結び付けたテーブルを作成して活用する。  
　　→ 必要なデータを付け加える

---

## 🔷 データベースの構成

**データベース ＝（複数の）テーブル（表形式で管理）**

- 構成要素：レコード（行）、カラム（列）
- ※ データは、フィールド（セル：升目）に格納され、関連あるデータはレコード単位で管理される。

> [!NOTE]  
> 💡 **イメージ：**  
> データベースとテーブルは、フォルダとファイルの関係に相当する。  

---

## 🔷 カラムとレコード

RDBにおいて、列のことを **カラム**、行のことを **レコード** と呼称し、基本的にレコード単位でデータは管理される。  
そしてレコードがたくさん集まった1つの表を **テーブル** という。

---

## 🔷 スキーマ

データベースに入力するデータはあらかじめ決定しておく必要がある。  
この決めた内容を **スキーマ** という。  
　　→ スキーマ：データベースの構造を表現する設計図（カラムごとに定義）

| 技術 | データ単位 | 定義 |
| --- | --- | --- |
| データベース | テーブル | ← スキーマ（カラムごとに定義） |
| Java | オブジェクト | ← クラス（フィールド宣言） |

⚠️ **データ保証について**（第4章で解説）  
テーブルの各項目に格納されているデータは、項目に該当するデータであることが保証されていなければならない！  


【保証されていない場合の例】  
- 誕生日のデータを取得するプログラムから電話番号が取得される
  　 → 論理エラー  
- データベース管理によって管理（定義）される  
   　　→ **スキーマ**：データベースの構造を表現する設計図（カラムごとに定義）

## 🔷 RDBMS の種類

※ RDB = Relational Data Base

**有償**

- Oracle Database ← 企業実習で扱う
- Microsoft SQL Server

**無償**

- MySQL ← 本訓練科目で扱う
- PostgreSQL ← MySQLと双璧をなす
※ 書店に行くと、上記二つの書籍が多く扱われている。
- H2 Database ← Javaサーバサイド編で扱う
