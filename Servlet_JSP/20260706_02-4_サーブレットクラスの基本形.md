## サーブレットの基本構造

```java
package com.example.servlet;

import java.io.IOException;
import java.io.PrintWriter;
import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;　//ルール①：インポート
/* メインパッケージ名
*   tomcat9 javax
*   tomcat10 jakarta
*/

@WebServlet("/sample")
public class SampleServlet extends HttpServlet {　//ルール②：継承

    // GETリクエストを処理する
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)　//ルール③：オーバーライド
            throws ServletException, IOException {

        // 文字コードとContent-Typeの設定
        response.setContentType("text/html; charset=UTF-8");

        PrintWriter out = response.getWriter();
        out.println("<html><body>");
        out.println("<h1>Hello, Servlet!</h1>");
        out.println("</body></html>");
    }

    // POSTリクエストを処理する
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        
        // 文字化け対策(リクエストの文字コード設定)
        request.setCharacterEncoding("UTF-8");

        String name = request.getParameter("name");

        // doGetを呼び出す、または別処理を書く
        doGet(request, response);
    }
}
```

## ポイント解説

| 要素 | 説明 |
|---|---|
| `extends HttpServlet` | すべてのサーブレットはこのクラスを継承する |
| `@WebServlet("/sample")` | URLパスとサーブレットを紐付けるアノテーション（web.xmlでの設定も可） |
| `doGet()` | GETリクエスト時に呼ばれるメソッド |
| `doPost()` | POSTリクエスト時に呼ばれるメソッド |
| `HttpServletRequest` | クライアントからのリクエスト情報を扱う |
| `HttpServletResponse` | クライアントへのレスポンスを組み立てる |
| `request.getParameter()` | フォームなどから送られたパラメータを取得 |
| `response.getWriter()` | レスポンスに文字列（HTMLなど）を書き込む |

## よく使う周辺メソッド

- `request.getRequestDispatcher("path").forward(request, response)` → JSPなどに処理を委譲(フォワード)
- `response.sendRedirect("path")` → リダイレクト
- `request.setAttribute(name, value)` → JSPに値を渡す
- `HttpSession session = request.getSession();` → セッション取得

## web.xmlの基本構造

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
             https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">

    <!-- アプリケーション全体の表示名 -->
    <display-name>SampleApplication</display-name>

    <!-- ようこそページ(トップページ)の指定 -->
    <welcome-file-list>
        <welcome-file>index.html</welcome-file>
        <welcome-file>index.jsp</welcome-file>
    </welcome-file-list>

    <!-- サーブレットの宣言 -->
    <servlet>
        <servlet-name>SampleServlet</servlet-name>  <!--サーブレット名-->
        <servlet-class>com.example.servlet.SampleServlet</servlet-class>    <!--サーブレットクラス名（完全限定クラス名）-->
    </servlet>

    <!-- サーブレットとURLパスのマッピング -->
    <servlet-mapping>
        <servlet-name>SampleServlet</servlet-name>  <!--サーブ絵っと名-->
        <url-pattern>/sample</url-pattern>  <!--URLパターン-->
    </servlet-mapping>

    <!-- 初期化パラメータ(任意) -->
    <context-param>
        <param-name>siteName</param-name>
        <param-value>My Sample Site</param-value>
    </context-param>

    <!-- エラーページの指定(任意) -->
    <error-page>
        <error-code>404</error-code>
        <location>/error/404.jsp</location>
    </error-page>

</web-app>
```

## ポイント解説

| 要素 | 説明 |
|---|---|
| `<web-app>` | ルート要素。バージョンやネームスペースを指定 |
| `<display-name>` | アプリケーションの名前(管理コンソールなどに表示) |
| `<welcome-file-list>` | URLの末尾がディレクトリの場合に表示する初期ファイル |
| `<servlet>` | サーブレットの実体(クラス)を登録するブロック |
| `<servlet-name>` | サーブレットを識別するための任意の名前(mappingと一致させる) |
| `<servlet-class>` | 実際のサーブレットクラスの完全修飾名(パッケージ込み) |
| `<servlet-mapping>` | どのURLにアクセスされたらどのサーブレットを呼ぶかの対応付け |
| `<url-pattern>` | クライアントがアクセスするURLパス |
| `<context-param>` | アプリ全体で共有する設定値(`ServletContext`から取得可能) |
| `<error-page>` | 特定のHTTPステータスコードや例外発生時の遷移先 |

## 補足:アノテーションとの関係

Servlet 3.0以降は `@WebServlet("/sample")` を使えばweb.xmlへの`<servlet>`/`<servlet-mapping>`記述は**省略可能**です。

- **アノテーション方式**:コードとマッピング情報が同じ場所にあり、見通しが良い(小規模向け)
- **web.xml方式**:設定を一元管理でき、コードを再コンパイルせずにURL変更が可能(大規模・運用重視向け)

授業や現場によってはweb.xmlを使う方針の場合もあるので、両方の書き方を知っておくと安心です。

必要であれば、`<filter>`(文字コード変換フィルタなど)や`<listener>`の設定例も追加できます。
