# JavaBeans

## 概要

JavaBeansとは、Javaで再利用可能なコンポーネントを作るための**設計規約（ルール）**のこと。特別なクラスというわけではなく、以下の条件を満たしたただのJavaクラスを指す。

主にJSP・Servletでデータを受け渡しする際の「データの入れ物（DTO/モデル）」として使われることが多い。

## JavaBeansの条件

1. **publicなクラス**であること
2. **引数なしのコンストラクタ**を持つこと
3. フィールドは**private**にすること（外部から直接アクセスさせない）
4. フィールドに対する**getter/setterメソッド**を用意すること
   - getter: `getXxx()`（boolean型は `isXxx()`）
   - setter: `setXxx(値)`
5. `Serializable`インターフェースを実装すること（推奨）

## サンプルコード

```java
import java.io.Serializable;

public class UserBean implements Serializable {
    private String name;
    private int age;

    // 引数なしコンストラクタ
    public UserBean() {
    }

    // getter
    public String getName() {
        return name;
    }

    // setter
    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

## JSPでの利用例

JSPには、JavaBeansを簡単に扱うための専用タグがある。

```jsp
<jsp:useBean id="user" class="sample.UserBean" scope="session" />
<jsp:setProperty name="user" property="name" value="Uni" />
<jsp:getProperty name="user" property="name" />
```

| タグ | 役割 |
|---|---|
| `<jsp:useBean>` | Beanのインスタンスを取得（なければ生成） |
| `<jsp:setProperty>` | setterを呼び出してプロパティを設定 |
| `<jsp:getProperty>` | getterを呼び出して値を出力 |

## なぜ使うのか

- **データとロジックの分離**：MVCモデルでいう「Model」の役割を担いやすい
- **セッション・リクエストスコープでのデータ保持**がしやすい
- フレームワーク（Spring等）でも、この規約に沿ったクラスが「Bean」として自動的に扱われる基礎になっている

## 補足：POJOとの違い

「POJO（Plain Old Java Object）」は単に特別な制約のないJavaオブジェクトを指す広い概念。JavaBeansはPOJOの中でも上記の規約（getter/setter・引数なしコンストラクタなど）を満たしたものを指す、より狭い概念。
