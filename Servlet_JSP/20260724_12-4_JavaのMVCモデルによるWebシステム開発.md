## JavaのMVCモデルによるWebシステム開発

Webシステムの開発では、処理を **Model（モデル）**・**View（ビュー）**・**Controller（コントローラー）** の3つの役割に分けて設計する「MVCモデル」という考え方が使われる。

### Model

- **Java SE**（Standard Edition）
- Javaの基本的な機能（変数、制御構文、クラス、コレクションなど）を使って実装される部分。

> 💡 補足
> ModelはDBアクセスやビジネスロジック（データの計算・加工など）を担当する部分。Servlet/JSPの学習では `Bean`（DTOやEntity）や `〜Service`、`〜Repository`（DAO）といったクラスがModelに該当する。

### Controller・View

- **Java EE**（Enterprise Edition）→ 現在は **Jakarta EE**
- ControllerとViewは、Java SEに加えてWebアプリケーション向けの拡張機能（Servlet、JSPなど）を提供するJava EE（Jakarta EE）の仕組みを使って実装される。

> ⚠️ 注意
> Java EEはバージョン9以降、**Jakarta EE** という名称で開発が進められるようになった（OracleからEclipse Foundationへ移管されたことに伴う名称変更）。パッケージ名も `javax.*` から `jakarta.*` に変わっている点に注意。

> 💡 補足
> MVCの対応関係を整理すると以下のようになる。
>
> | 役割 | 技術 | 主な担当 |
> | --- | --- | --- |
> | Model | Java SE | データ処理・ビジネスロジック |
> | Controller | Java EE（Jakarta EE）＝ Servlet | リクエスト制御・処理の振り分け |
> | View | Java EE（Jakarta EE）＝ JSP | 画面表示 |

## システム開発の歴史

Webシステム開発技術は、以下のような流れで発展してきた。

**サーブレット → サーブレット＋JSP → フレームワーク**

> 💡 補足
> - **サーブレットのみの時代**：ロジックも画面出力（HTML）もすべてJavaコード（サーブレット）内に書いていたため、画面デザインの変更のたびにJavaコードを修正・再コンパイルする必要があり、非効率だった。
> - **サーブレット＋JSPの時代**：JSPの登場により、画面表示（View）をJSPが、処理の制御（Controller）をサーブレットが担当するようになり、役割分担（初期のMVC的な構成）が可能になった。
> - **フレームワークの時代**：Spring（Spring MVC / Spring Boot）などのフレームワークが登場し、MVCモデルに基づいた設計や、DI（依存性注入）、設定の自動化などにより、開発効率・保守性がさらに向上した。

## JavaでのWebシステム開発とフレームワーク

JavaでWebシステム開発を行う際は、便利な機能やライブラリを利用できる **フレームワーク** を使うことが主流である。

### Java SEでの開発（ライブラリ追加型）

クラスの集合である「ライブラリ」を、必要に応じてプログラムに追加していく方式。

### Java EEでの開発（ひな型活用型）

あらかじめ用意されているひな型（雛形）を土台にして、プログラムに必要な機能を追加していく方式。

> 💡 補足
> Java SEの「ライブラリを都度追加していく」開発スタイルに対して、Java EE（Jakarta EE）やSpringなどのフレームワークは「土台（ひな型）がすでに用意されていて、そこに肉付けしていく」開発スタイルという違いがある。ゼロから組み立てるか、決まった型に沿って作るかの違いとイメージすると分かりやすい。

フレームワークを活用することで、経験の浅いプログラマでも、Web対応用のJava技術であるサーブレット/JSPを使ったWebシステムを効率よく開発しやすくなる。

## プロジェクト管理ツール「Maven」

フレームワークで広く採用されているプロジェクト管理ツールに **Maven** がある。

Mavenを利用したライブラリの管理は、管理するプロジェクトの定義情報を記述した **`pom.xml`** ファイルで、利用するライブラリの管理を行うことができる。

> 💡 補足
> `pom.xml` には、プロジェクトの基本情報（groupId / artifactId / version など）に加えて `<dependencies>` タグで使用するライブラリ（依存関係）を記述する。Mavenはこの記述をもとに、必要なライブラリを自動でダウンロード・管理してくれるため、手動でjarファイルを集めて配置する手間が省ける。Spring Bootプロジェクトでも標準的に使われているビルドツールの1つ（もう1つの代表的なツールが `Gradle`）。

■pom.xmlによるライブラリの管理概要
Mavenは「pom.xml」を元にローカルリポジトリを探して必要なファイルを読み込む。
その際にローカルリポジトリに必要なjarファイルが無ければ、リモートリポジトリを探してDLし、ローカルリポジトリに「配置する」。

pom.xmlによるライブラリの管理方法
1. 必要なライブラリの情報は、Mavenリポジトリサイトで検索できるようになっている。
2. 公開されているコードをpom.xmlに追記する
   ※記述場所`</build>`タグの後に`<dependencies>`要素を用意し、その内容として記述する
