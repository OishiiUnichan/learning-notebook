## JDBCとは

**JDBC（Java DataBase Connectivity）**
JavaアプリケーションからDBを操作するためのAPI。

> [!NOTE]
> DBアクセスには、JDBCドライバと呼ばれるライブラリ（JARファイル）が別途必要になる。

## JDBCを構成する5つの要素

| No. | クラス／インターフェース | 役割 |
|---|---|---|
| 1 | `DriverManager` | DBMSへの接続準備を行う |
| 2 | `Connection` | DBMSへの接続・切断を行う |
| 3 | `PreparedStatement` | SQLの送信を行う |
| 4 | `ResultSet` | DBMSから検索結果を受け取る |
| 5 | `SQLException` | DBに関するエラー情報を提供する |

## JDBCがある場合／ない場合の比較

| | JDBCが**ない**とき | JDBCが**ある**とき |
|---|---|---|
| DB変更時の対応 | コードをすべて変更する必要がある | 接続設定を変更するだけでよい |
| 命令の扱い | 各DBごとに異なる命令を使い分ける必要がある | 共通の命令でDBにアクセスできる |
| 開発者への負担 | 各DBの命令を個別に習得する必要がある | 各DB独自の命令を新たに習得する必要はない |

> [!TIP]
> JDBCは「DBの種類が変わっても、Javaコード側の書き方は変えなくていい」ようにするための共通インターフェース、というイメージ。

## H2 DB

DBサーバーの指定方法は接続URLのプレフィックスによって変わる。

| 接続URL | モード | 説明 |
|---|---|---|
| `jdbc:h2:tcp:...` | サーバーモード | 起動しているH2サーバーに接続するための指定 |
| `jdbc:h2:file:...` | 組み込みモード | ファイルベースでH2DBに直接アクセスするための指定 |

> [!NOTE]
> `~` はホームディレクトリを表す。Windowsの場合は、使用中のアカウントと同じ名前のフォルダを指す。

## JDBCプログラムの流れ

| No. | クラス／メソッド | 役割 |
|---|---|---|
| 1 | `DriverManager.getConnection()` | DBに接続する |
| 2 | `Connection.prepareStatement()` | SQL発行の準備をする |
| 3 | `PreparedStatement` | 準備したSQLを保持する |
| 4a | `PreparedStatement.executeQuery()` | 検索（SELECT文）を実行し、結果を `ResultSet` に格納する |
| 4b | `PreparedStatement.executeUpdate()` | 更新（INSERT文・UPDATE文・DELETE文）を実行し、更新した行数（`int`）を返す |

> [!TIP]
> SELECTは「結果セットが欲しい」から `ResultSet` を返す `executeQuery()`、INSERT/UPDATE/DELETEは「何件変わったか」が欲しいから `int` を返す `executeUpdate()`、と使い分けると覚えやすい。

## ResultSetのnext()の動作

`next()` は、次のレコードが存在するかどうかを `true`／`false` で返す。

- レコードが**存在する** → `true`
- レコードが**存在しない** → `false`

> [!NOTE]
> `next()` の戻り値を `while` の条件式として利用することで、`ResultSet` に格納されているレコードの件数分だけ繰り返し処理を実行できる。

```java
while (rs.next()) {
    // レコードが存在する間、処理を繰り返す
}
```

## RDBMSの型とResultSetのメソッド対応

`ResultSet` から値を取り出す際は、RDBMSで定義されている型とJavaの型の対応を考えて、適切なメソッドを選択する。

| RDBMSの型 | 対応するJavaの型 | ResultSetのメソッド |
|---|---|---|
| `INT` / `INTEGER` | `int` | `getInt()` |
| `FLOAT` / `DOUBLE` | `double` | `getDouble()` |
| `DECIMAL` | `BigDecimal` | `getBigDecimal()` |
| `DATE` / `DATETIME` | `Date` | `getDate()` |
| `CHAR` / `VARCHAR` | `String` | `getString()` |

> [!NOTE]
> 型を間違えたメソッドを呼び出すと、意図しない変換が起きたり例外が発生したりする。カラムの型を確認してから対応するメソッドを選ぶこと。

## DAOパターン

**DAO（Data Access Object）パターン**
DBへのアクセス処理（JDBCのコード）を、他のロジック（画面制御やビジネスロジック）から切り離して1箇所にまとめる設計パターン。

> [!NOTE]
> 「テーブル1つにつきDAOクラス1つ」が基本の考え方。例：`UserDao`、`MovieDao` など。

### なぜ使うか

| DAOがないとき | DAOがあるとき |
|---|---|
| Servletの中にSQLやJDBCの処理が混在する | ServletはDAOを呼び出すだけになる |
| DB操作のコードが色々な場所に散らばる | DB操作の窓口が1箇所にまとまる |
| SQLを直す時に画面制御のコードまで探す必要がある | DAOクラスだけ直せばよい |

### 基本構成

| 役割 | 内容 |
|---|---|
| DAOクラス | 特定のテーブルに対するCRUD処理（`insert`・`select`・`update`・`delete`）をメソッドとして持つ |
| 呼び出し側（Servletなど） | DAOのメソッドを呼ぶだけで、SQLやJDBCの詳細は意識しない |
| 戻り値 | 検索結果は `ResultSet` のまま返さず、Beanクラス（例：`Movie`）やそのリストに変換して返す |

```java
public class MovieDao {
    public List<Movie> findAll() {
        // Connection取得 → SQL実行 → ResultSetをMovieのリストに変換して返す
    }
}
```

> [!TIP]
> `ResultSet` はConnectionを閉じると使えなくなるため、DAOの中で必ずBeanクラスに詰め替えてから返すのがポイント。
