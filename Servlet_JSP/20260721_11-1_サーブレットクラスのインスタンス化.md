# 11-1_サーブレットクラスのインスタンス化

subject: Servlet_JSP  
day: 2026年07月21日  
memo:  

---


## 結論

サーブレットのインスタンスは **開発者が `new` で作るのではなく、Webコンテナ（Tomcatなど）が自動で生成する**。

---

## いつ生成される？

- 基本的に **サーブレットへの最初のリクエストが来たとき** に1回だけ生成される
- `web.xml` や `@WebServlet` の設定で `load-on-startup` を指定すると、**サーバー起動時** に生成することも可能

```java
@WebServlet(urlPatterns = "/hello", loadOnStartup = 1)
public class HelloServlet extends HttpServlet {
    // ...
}
```

---

## 何個インスタンスが作られる？

> [!IMPORTANT]
> 原則として **1つのサーブレットクラスにつき、インスタンスは1個だけ**（シングルトン）。

同時に複数のリクエストが来ても、**同じインスタンスが使い回される**（マルチスレッドで並行実行される）。

```
リクエストA ─┐
リクエストB ─┼─→ 同じHelloServletインスタンス
リクエストC ─┘
```

---

## コンテナが自動生成する流れ（ライフサイクル）

1. **インスタンス生成**：コンストラクタが呼ばれる
2. **`init()`**：初期化処理（最初の1回だけ）
3. **`service()`**（→ `doGet()` / `doPost()` など）：リクエストのたびに毎回呼ばれる
4. **`destroy()`**：サーバー停止時などに1回だけ呼ばれる

```java
public class HelloServlet extends HttpServlet {

    @Override
    public void init() {
        // 初期化処理（1回だけ）
    }

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        // リクエストのたびに呼ばれる
    }

    @Override
    public void destroy() {
        // 終了処理（1回だけ）
    }
}
```

---

## なぜインスタンスを使い回すのか？

| 理由 | 説明 |
|---|---|
| パフォーマンス | リクエストのたびに `new` すると生成コストがかかるため |
| リソース効率 | インスタンス生成・破棄の手間を最小限にできる |

---

## 注意点：インスタンス変数の共有に気をつける

インスタンスが1個しかない＝**インスタンス変数（フィールド）は全リクエストで共有される**。

```java
public class CounterServlet extends HttpServlet {
    private int count = 0; // ⚠️ 全リクエストで共有される！

    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        count++; // 複数ユーザーが同時アクセスすると危険（スレッドセーフでない）
    }
}
```

> [!WARNING]
> リクエストごとに独立させたいデータは、フィールドではなく **ローカル変数** や **リクエストスコープ（`request.setAttribute()`）** を使うこと。

---

## まとめ

- サーブレットのインスタンス化は **コンテナが自動で行う**
- 通常は **1インスタンスのみ生成され、使い回される**
- そのため **インスタンス変数の共有** に注意が必要
