## SQLインジェクションとは

アプリケーションが想定しないSQL文を実行させることにより、DBを不正に操作する攻撃方法。また、その攻撃を可能とする脆弱性のこと。

## 想定される被害

- 非公開情報の漏洩
- 情報改ざん
- データ削除・破壊
- 認証回避による不正ログイン
- など

## 事例：どこつぶへの攻撃

> [!WARNING]
> 以下は攻撃の仕組みを理解するための例。実際のアプリケーションでは対策が必須。

1. 「怪盗ルパン」としてログインする
2. つぶやき入力欄に、以下の文字列を入力する

   ```
   これまでのつぶやきを頂きに参ります');　DELETE FROM MUTTERS; --
   ```

3. 入力値がそのままSQL文に組み込まれると、以下のように発行されてしまう

   ```sql
   INSERT INTO MUTTERS(NAME, TEXT) VALUES('怪盗ルパン', 'これまでのつぶやきを頂きに参ります');  -- INSERT文の完成
   DELETE FROM MUTTERS;    -- MUTTERSテーブルの全レコードを削除
   --');                    -- 残りはコメント文として扱われる
   ```

> [!IMPORTANT]
> 本来1件のつぶやきを登録するだけのはずが、入力値に紛れ込んだ `);` によってSQL文が2つに分断され、後半の `DELETE FROM MUTTERS;` が別の命令として実行されてしまう。

## 対策

### 1. プレースホルダーを使う

**プレースホルダー**：あとから入力されるデータの代わりに、仮に入力しておく記号（`?`）のこと。

```sql
INSERT INTO MUTTERS(NAME, TEXT) VALUES(?, ?);
```

> [!NOTE]
> SQL文の準備段階で構文が確定するため、それ以降にSQL構文が変化することはなく、SQL文を安全に発行できる。構文確定後に入力値を設定すると、その値は単なる文字列として扱われる（＝SQL命令として解釈されない）。

**書式**

```java
PreparedStatement#set + データ型に対応するメソッド名（引数の位置, 登録データ）;
```

### 2. 保険的な対策

適切な文字数制限や入力値の検証も有効な対策になる。

> [!NOTE]
> - プログラムコードとして成立させるには、ある程度の文字数が必要になる（極端な文字数制限自体が一定の防御になる）
> - 正規表現によるチェックは、ブラウザ側（フロントエンド）だけでなく、サーバーサイドでも必ず実施する
