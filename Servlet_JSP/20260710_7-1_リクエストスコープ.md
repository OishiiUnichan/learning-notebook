## 7-1　スコープの基本

### フォワード転送 → データ連携

<img width="1880" height="1240" alt="scope_flow" src="https://github.com/user-attachments/assets/7735a4a1-79cd-4c33-8c89-753335bf7765" />

1. ブラウザがサーブレットに **リクエスト** を送る
2. サーブレットが String インスタンスを **生成** する
3. サーブレットが JSP ファイルへ **フォワード** する
4. String インスタンスは **スコープ**（インスタンスを保存できる領域）に **保存** される
5. JSP ファイルはスコープからインスタンスを **取得** する
6. JSP ファイルが画面を出力し、**レスポンス** としてブラウザに返る

> [!WARNING]
> スコープには**有効期限**がある！！

### JavaBeans：関連する複数の方法を、ひとまとめにして保存

#### ルール① `java.io.Serializable` インターフェイスを実装

> [!NOTE]
> **マーカーとしての役割**
> `Serializable` はメソッドをもたない「マーカーインターフェイス」である。これを実装することで、Java のシステムに対して「このクラスは安全にシリアライズ（外部媒体に保存）して問題ないデータである」と許可を与える意味を持つ。

#### ルール② クラスは、public でパッケージに所属

#### ルール③ public で引数のないコンストラクタをもつ

> [!NOTE]
> **手順の統一**
> 「まずは、空のインスタンスを作る」→「次に、Setter でデータを詰める」という、一連の手順を統一・自動化するために必要となる。

#### ルール④ フィールドは、カプセル化する

命名規則に従った getter/setter をもつ

- getter＝プロパティを読み取る
- setter＝プロパティを変更する

| 用語 | 意味 |
|---|---|
| フィールド | クラスの内部でデータを保持する変数そのもの |
| プロパティ | getter や setter を通じて、外部に公開されるデータの「概念」 |

| 項目 | フィールド (field) | プロパティ (property) |
|---|---|---|
| 本質 | 内部の変数 | 外部向けのアクセス窓口 |
| 修飾子 | 原則、private | 原則、public（メソッドとして公開） |
| 命名規則 | 自由（例：myAge） | メソッド名に依存（例：isAdult なら adult） |
| 存在条件 | コード上で変数を宣言 | getter または setter を定義 |
