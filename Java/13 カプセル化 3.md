# カプセル化を支えている考え方

- カプセル化の由来
    
    あるクラスが外部から直接アクセスされないように、メソッドという殻によってフィールドを保護している。
    
    →メソッドのブロックの中の処理でフィールドを処理する
    
- 保護対象がフィールドである理由
    
    プログラム実行中に
    
    - メソッドは処理内容が変わることはないが（命令文だから？）
    - フィールド内部は刻々と変わっていく（再代入の繰り返し）
    - フィールドに想定外の値が代入される可能性がある
        
        →プログラムの不具合につながる
        
    
    ※オブジェクト指向3大機能のうち、カプセル化はオブジェクト指向を支える根元の機能である。
    
    →クラス設計する際は、適切にカプセル化を施しておけばインスタンスのフィールドを直接外部にさらすことなく、互いに公開したアクセサ（getterとsetterの総称）やほかのメソッドを呼び合うことで安全に連携させることができる。
