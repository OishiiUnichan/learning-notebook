# 7.1 オブジェクト指向のことはじめ（学ぶ理由）

- 制御構造を組み合わせることで、理論上複雑かつ大規模なプログラムが作成可能になる。
    
    ［構造化定理：第3章］
    
    ［受注側］〇　コンピュータ：時代とともに演算性能や記憶容量の進展
    
    ［発注側］×（開発者）：大量のソースコードを把握・管理できない←ボトルネック
    
    →その対策として、プログラミング方法論の検討：オブジェクト指向の概念を取り入れる［前提：大規模プログラムの作成］
    
    ※手続き指向（1部）とオブジェクト指向（2部）の違いは「方法論」
    
    →どちらの方法論でも目的は達成できる
    
    →**学習意識の切り替えが大事**
    

## ［イメージ］遠距離の移動手段

手続き指向）公共機関の乗り継ぎ（手順）を考える

［例］普通列車→急行列車：手段は変えない

オブジェクト指向）公共機関の乗り**換え**（役割）を考える

［例］高速バス→飛行機：手段を変える

※プログラミングに必要な能力＝２つの『そうぞう』力

|  | 第一部：手続き指向 | 第二部：プロジェクト指向 |
| --- | --- | --- |
| 想像力 | アイデア（斬新）
［例］列車の路線図、時刻表 | イメージ（描写）
［例］飛行機で移動、船で移動 |
| 創造力 | 処理方法（手順、段取り）
［例］普通から急行に乗り継ぐ | 操作方法（役割、相互作用）
［例］バスから飛行機に乗り換える |

※オブジェクト指向の学習において、概念を理解することやイメージすることをより重要視する必要がある。

## ★オブジェクト指向の「 捉え方 」「 考え方 」の整理

［図7-2］ （P.259）

「第Ⅰ部 手続き指向」と「第Ⅱ部 オブジェクト指向」で、できることが異なるように思えるが、両者の違いは「方法論」であって、どちらの方法論でも同じ目的を達成することはできる。

［例］ カレーをつくる

手続き指向）

「万能」型ロボットにカレーのレシピを（作業指示書）を渡して、カレーを作ってもらう。

→内容を把握しきれないならば、作業対象に機能を用意しておけばいい！

オブジェクト指向）

「専用」型ロボットにカレーをつくる機能を搭載し、「万能」型ロボットからカレーをつくってもらう指示を出す。

［比較］

手続き指向）炊飯のレシピがあれば、複雑な手順でも、だれもが炊飯できる。

オフジェクト指向）炊飯器があれば、簡単な操作で、誰もが炊飯できる。

［特徴］手続き指向 VS オブジェクト指向

→　カレー作りに必要な機能は、ポトフやシチューがあれば、再利用できる。

手続き指向）レシピを知っていない対応できない！レシピ全体の作り直しが必要になる	　［再利用不可］

オブジェクト指向）	対象物を作り直さなくても必要な機能の追加、修正で対応可能になる　［再利用可能］

## 〇オブジェクト指向の目的

- 「人間が把握しきれない複雑さ」を克服するために生まれた。
- 大規模なプログラムもラクに開発できるようになった。
