# 配列の後片付け（ガベージコレクション）

スタック領域で確保した領域

→　処理が変数宣言したブロックの外に出た時点で消滅する

ヒープ領域に確保した領域

→　処理が変数宣言したブロックの外に出た時点でも残る
※参照できないデータは事実上メモリ内のごみになり、メモリを圧迫することになる

→　本来ならば、メモリの後片付けをプログラムに明記する必要がある
→　javaには、ガベージコレクションという機能があり、自動的にごみを破棄してくれる

（当時は先進的な機能だったが、現在では搭載されている言語もある）

# ★null

イメージ：壊れたリモコン

1. 参照型変数に代入できるが、基本型変数には代入できない。
2. 参照型変数に代入すると、参照できない状態になる。←「参照を切る」という。
    
    意図的にガベージコレクションの対象とすることもできる。
    

参照型の値としても扱うことはできるので、値として表示することは可能。
（壊れていてもリモコンはリモコンとして存在する）

例）

```java
String[] str=null;
System.out.println(null);　→　nullと表示される

一方、参照しようとするとエラーを吐く
String[] str = null;
System.ou.println(str[0]);　→　NullPointerException
```

# 多次元配列

現実的には人がイメージできる2～3次元配列の使用

→　データを表形式で管理したいときに使用
[ 参考]表形式で出力したいときはfor文の二重構造を使用する

```java
[宣言]２次元配列の場合
要素の型[][] 配列変数名　= new 要素の型[行][列]; // 要素数で指定
　　int[][]　scores　　 = new     int[2][3];

[要素の指定]2次元配列の場合
配列変数名[行の添え字][列の添え字] //添え字で指定
scores　　　[2]　　　　　[3];　　　//2行3列の表

[仕込み]2次元配列の場合
	→　要素の中に別の配列の要素を入れ子にする
	
int[][] scores = {{40,50,60},　　//scores[0]
									{80,60,70}};　//scores[1]
									
										↑１行で記述しなくてもよい
```
