# メソッド

関連ある内容でまとめる作業を「部品化」という。

→　クラスやメソッド単位でまとめる作業を指す。

メソッド：複数の処理文をまとめ、１つの処理として呼び出せるように名前を付けた部品のこと。文章で例えると、関連ある内容をまとめて見出しを付ける作業。

### [ メソッドごとに部品化するメリット ]

1. プログラムの見通しが良くなる　→　大局を見渡せる（文書の目次に相当）
2. 関連ある内容でまとめるため、修正範囲が限定しやすい
3. 同じ処理内容を効率よく実施しやすくなるため、冗長性をなくすことができる。

### [ メソッドの定義 ]

```java
pubulic static void main(String [] args){ ... } // ex)mainメソッド
1.main...メソッド名：自販機の名前
2.String[] args...引数リスト：現金通貨投入口
3.void...戻り値の型：取り出し口に提供される商品の種類
```

### [ メソッドの呼び出し] 命令実行の文｜２.６節

1. main()メソッドが最初に実行される
2. main()メソッドのブロック内でほかのメソッドの呼び出しを記述する
3. 呼び出したメソッドの処理が終了すると、処理の流れが呼び出し元に戻って処理が続行される

[ 書式 ]

```java
所属.メソッド名（引数リスト）;
　↑同じクラスの場合、省略可能
```

　※　メソッドは定義しただけでは実行されない

→　呼び出されることで定義したメソッドが実行される

![image.png](5%20%E3%83%A1%E3%82%BD%E3%83%83%E3%83%89%EF%BC%88%EF%BC%91%EF%BC%89/image.png)

#### 補足

1. 処理の流れの中で会えば、main()メソッド以外のメソッドからほかのメソッドを呼び出せる
2. maiメソッドを含め、ほかのメソッドの定義の並び順と実行する順番に関連はない
    
    まず、main()メソッドが実行される。ほかのメソッドは、処理の流れの呼び出し順に従い実行される。
    

[ メモ ]

Eclipseのような統合開発環境でプログラミングする場合、未定義のメソッドの呼び出しはコンパイルエラーになるため、先にメソッドを定義するとコンパイルエラーの表示防止ができる。

一方、プログラム全体の流れを考慮してプログラミングする場合は、後でメソッドを定義することになる（**段階的詳細化**）

※　どちらの書き方を採用するかはプログラムの規模と現場による

### メソッドを定義するうえでの注意事項

☆『メソッド名』は定義する立場においても、利用する立場においても、処理内容が想像しやすい名前にする

※大規模プロジェクトの開発現場では開発者が手分けして作業する

→　メソッドを定義する人と、呼び出して利用する人は異なる

→　定義す人は呼び出す人のことを考えて、メソッド名を決める必要がある

[ メソッドの定義 ]

```java
１　public static void hello(){　　　//宣言　　←
２　	System.out.println("こんにちは");　　　　←全部ひっくるめて定義
３　}　　　　　　　　　　　　　　　　　　　　　　←
```

１を「宣言」と呼ぶ

利用者にとって、メソッド呼び出しに必要な情報

　１～３のすべてを含んだ記述部を「定義」と呼ぶ

２の処理内容は利用者には重要ではない
