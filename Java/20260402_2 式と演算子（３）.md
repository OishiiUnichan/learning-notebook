# 型の変換

## 1.代入時の自動変換

floatの中にint型代入可
doubleの中にfloat型にも代入できる

```jsx
int i = 3.2; //エラーになる
float m = 3; //エラーにならない
byte j = 2; //エラーにならない
```

上記コードがエラーになる理由・・・
int（整数型）に3.2（小数）が入っているから
整数よりも小数の方が情報量が多い（大きい）ためエラーになる

**☝️小さな型の中に大きな型の値は変数として代入できない**

## 2.演算時の自動変換

```jsx
①double d = 5.0 / 2;　//int型をdouble型に変換して計算する
②String msg ="私の年齢は" + 23; //int型がString型に変換されて連結される
```

#### 3.強制的な型変換

```jsx
int age = (int)3.2;
```

---

double型を強制的に変換している
強制的な型変換を指示するキャスト演算子と呼ぶ
ただし、情報が失われるのでよほどの理由がない限り使わない

【原則】演算子の左右のオペランドは、同じ型であることが要求される
→使い勝手がいいため、Javaには型を変換する仕組みが3つ備わっている。

①代入時の型変換（自動）
数値型には『意味』的な大小関係が定められている（図2-8［p.081］)。
１．整数型 ＜ 少数型：整数型 ）数値のみの管理
少数型 ）数値に加えて、小数点の位置も管理
２。整数型：桁数の大きさがそのまま適用される
( byte < short < int < long )
３.少数型：制度の高さがそのまま適用される
( float < double )

※代入時の型変換とは、
　意味的に「小さな型」の値を「大きな型」の変数に代入する場合、
　［例］		int型	  3     double型	  d
　代入される値が代入先の変数の型に自動的に変換されてから代入が行われる。
　［例］　　　３　　　　　double型　　　　　3.0

【例外】byte型やshort型の変数に対して、byte型やshoat型のリテラルは存在しない！
［例］３(int型)３L(long型） *３B　＊３S
そこで
『実害のない範囲』でint型のリテラルを代入することは認められている。
→byte型：±約128、　short型：±約3万
