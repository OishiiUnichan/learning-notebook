# 多態性

［イメージ］

1. あるものをあえてざっくり捉える
    
    →　これまでの学習内容は、変数宣言で定めたデータ型と同じ型の値しか代入できない
    
2. ざっくり捉えることにより、得られるメリットを享受する
    
    ［例］初めてのレンタカーでも無難に運転できる
    
    →車種に限らず、構造はほぼ同じ
    
- 厳密には異なるが、似たようなものとして活用する機能→**多態性**

## ザックリ捉える方法

- 他の2大機能と異なり、特別な構文はなく、変数への代入を緩く行う
    
    →代入式の左辺と右辺で厳密には同じ型でなくともよい
    
    →継承元のクラス型に継承先のインスタンスを代入できる
    

［前提］代入式の左辺と右辺で、is-aの関係が成立していること

［例］SuperHeroはCharacterの一種である。

→◎Character c = new SuperHero();

［手段］正しい継承関係で継承先のクラスを作成すること。

→extendsやimplementsは、クラスをよりよく定義すうだけではなく、Javaに正しい継承関係を伝える手段でもある。

※クラス型について

- 新しくクラスを設計すると、そのインスタンスを代入できる型が使えるようになる［8章］

［抽象クラスやインターフェースの型］

✕　抽象クラスやインターフェースからインスタンスを生み出すことはできない［11章］

〇　抽象クラスやインターフェースの型を利用することはできる。［8章］

# 捉え方を変更する方法

※ コンパイラは基本的にプログラムを１行ずつ解釈、翻訳しようとする。

→ 失敗する可能性のある代入は拒否される（コンパイルエラー）！
　［例］

```java
Character c = new Wizard();	//	（1）
Wizard w = c;			//	（2）
```

（１）の実行結果を

知っている場合 → 代入は「成功」する！

知らない場合 → （２）の代入は「失敗」する可能性がある！？

※ 変数cにWizardインスタンス以外のインスタンスが格納されている可能性も考えられる！

→ 強制的に型変換（キャスト）すれば、コンパイルは通るようになる！

［例］

`w = (Wizard) c;`

→ ダウンキャスト

『あいまい』な型に入っている中身を

『厳密』な型に代入するキャスト

→ しかし、実行時除外（ClassCastException）が発生する可能性がある！

（上記の例の場合、Heroインスタンスが格納されている場合など）

［対策］

instanceof演算子の利用

→ 安全にキャスト可能か否かを事前に判定する。

# 多態性のメリット

- ザックリ捉えるメリット
    1. メソッドの動作は変数の中身の型に従う [ 12-3節 ]
        
        → インスタンスは親クラスの型の箱に入っていようとも、自身のクラス型のメソッドが動作する。
        
    2. 異なるインスタンスを同一視してまとめて扱うことができる ［12-5節］。
        
        → 親クラス型の配列および引数を利用して、厳密には異なるインスタンスをまとめて扱うことができる。
