# Javaの「例外処理」を理解しよう！

---

## 🔴 まず「エラー」の種類を知ろう

Javaのエラーには大きく **3種類** あります。

| 種類 | 内容 | 例 |
| --- | --- | --- |
| **文法エラー** | コードの書き方（構文）が間違っている | `int x = ;` のように書いた |
| **実行時エラー** | プログラムを動かしたときに起きる | 0で割り算しようとした |
| **論理エラー** | プログラムは動くが、結果がおかしい | 消費税を1.1倍ではなく0.1倍で計算した |

> 💡 **例外処理**で対応できるのは、主に「**実行時エラー**」です！
> 

---

## 🔵 「例外的状況」と「例外処理」とは？

プログラムを動かしていると、想定外のことが起きることがあります。これを **例外的状況** といいます。

たとえば…

- 存在しないファイルを開こうとした
- 配列の範囲外にアクセスしようとした
- `null`（何もない）のオブジェクトを使おうとした

こうした「まずいこと」が起きたときに、プログラムをクラッシュさせずに**うまく対処する仕組み**が **例外処理** です。

---

## 🟢 例外クラスの種類

Javaでは例外を「クラス」として表します。例外クラスには **3つの系統** があります。

```
Throwable（すべての例外・エラーの親）
├── ① Error系例外（エラー系例外）
│     └── OutOfMemoryError, StackOverflowError など
│         👉 JVM（Java実行環境）の深刻な問題。基本的に対処しない。
│
└── Exception（例外の基本）
      ├── ② Exception系例外
      │     └── IOException, SQLException など
      │         👉 「チェック例外」。必ず例外処理が必要！
      │
      └── RuntimeException
            └── ③ RuntimeException系例外
                  └── NullPointerException, ArrayIndexOutOfBoundsException など
                      👉 「非チェック例外」。プログラマのミスが多い。
```

## 🟡 try-catch文の基本

例外処理の基本構文は **try-catch文** です。

```java
public class TryCatchSample {
    public static void main(String[] args) {

        try {
            // 🔵 ここに「危ないかもしれない」コードを書く
            int answer = 10 / 0;  // 0で割ると例外が発生！
            System.out.println("答えは: " + answer);

        } catch (ArithmeticException e) {
            // 🔴 例外が発生したときの対処を書く
            // 「e」が「例外インスタンス」（例外の情報が入ったオブジェクト）
            System.out.println("エラーが起きました: " + e.getMessage());
        }

        System.out.println("プログラムは止まらず続きます！");
    }
}
```

**実行結果**

```
エラーが起きました: / by zero
プログラムは止まらず続きます！
```

> 💡 `catch` のカッコ内の `e` が **例外インスタンス** です。例外の詳細情報（メッセージやスタックトレース）を持っています。
>

## 🟣 NullPointerException を体験しよう

**NullPointerException** は最もよく見るエラーのひとつ。`null`（何もない）に対して操作しようとすると発生します。

```java
public class NullPointerSample {
    public static void main(String[] args) {

        String name = null;  // nameには何も入っていない

        try {
            // nullのオブジェクトのメソッドを呼ぶと NullPointerException が発生！
            System.out.println(name.length());

        } catch (NullPointerException e) {
            System.out.println("nullのオブジェクトを使おうとしました！");
            System.out.println("詳細: " + e.getMessage());
        }
    }
}
```

**実行結果**

```
nullのオブジェクトを使おうとしました！
詳細: Cannot invoke "String.length()" because "name" is null
```

## 🔶 finally ブロック

`finally` は **例外が起きても起きなくても、必ず実行される** ブロックです。

ファイルや通信の「後片付け」に使います。

```java
public class FinallyExample {
    public static void main(String[] args) {

        try {
            System.out.println("処理を開始します");
            int result = 10 / 0;  // 例外が発生！
            System.out.println("この行は実行されない");

        } catch (ArithmeticException e) {
            System.out.println("例外をキャッチしました: " + e.getMessage());

        } finally {
            // 例外があってもなくても、ここは必ず実行される！
            System.out.println("finally: 後片付け完了！");
        }
    }
}
```

**実行結果**

```
処理を開始します
例外をキャッチしました: / by zero
finally: 後片付け完了！
```

## 🔷 try-with-resources（自動クローズ）

ファイルなどのリソースを使うとき、使い終わったら必ず「閉じる」必要があります。
**try-with-resources** を使うと、自動的に閉じてくれます。

```java
import java.io.*;

public class TryWithResourcesSample {
    public static void main(String[] args) {

        // try(...) の中でリソースを宣言すると、終了時に自動でclose()される
        try (BufferedReader reader = new BufferedReader(new FileReader("sample.txt"))) {

            String line = reader.readLine();
            System.out.println("読み込んだ内容: " + line);

        } catch (IOException e) {
            // ② Exception系例外（IOExceptionはチェック例外）
            System.out.println("ファイルが見つかりません: " + e.getMessage());
        }
        // readerは自動的にclose()される（finallyを自分で書かなくてOK！）
    }
}
```

> 💡 `try-with-resources` は **`AutoCloseable`** インターフェースを実装したクラスに使えます。`finally { reader.close(); }` を自動でやってくれる便利な書き方です！
>

## 📊 まとめ：try-catch / finally / try-with-resources の使い分け

| 構文 | 使いどころ |
| --- | --- |
| `try-catch` | 例外が起きそうな処理を囲んで、エラー時に対処する |
| `finally` | 例外の有無に関わらず必ず実行したい後片付け処理 |
| `try-with-resources` | ファイル・通信など「閉じる必要があるリソース」を扱うとき |

## 🌊 例外の伝播（でんぱ）

例外が発生したとき、その場でcatchされなければ、**呼び出し元のメソッドへとどんどん伝わっていきます**。これを **例外の伝播** といいます。

```
methodC() で例外発生
  ↓ catchされなかった
methodB() へ伝わる
  ↓ catchされなかった
methodA() へ伝わる
  ↓ ここでcatch！
```

```java
public class PropagationSample {

    // methodC：例外が発生する場所
    static void methodC() {
        int result = 10 / 0;  // ArithmeticException が発生！
    }

    // methodB：catchせずにそのまま上へ伝わる
    static void methodB() {
        methodC();  // 例外はここを素通りして伝播する
    }

    // methodA：最終的にここでcatchする
    static void methodA() {
        try {
            methodB();
        } catch (ArithmeticException e) {
            System.out.println("methodA でキャッチしました: " + e.getMessage());
        }
    }

    public static void main(String[] args) {
        methodA();
        System.out.println("プログラム正常終了");
    }
}
```

**実行結果**

```
methodA でキャッチしました: / by zero
プログラム正常終了
```

> 💡 どこにもcatchされなければ最終的にプログラムが**強制終了**します。どこかで必ず受け取る設計が大切です！
>

## 📢 チェック例外の伝播とスロー宣言（throws）

**チェック例外（② Exception系）** は特別なルールがあります。
メソッド内でcatchしない場合、**「この例外が出るかもしれません」と宣言する義務** があります。これを **スロー宣言（`throws`）** といいます。

```java
import java.io.*;

public class ThrowsSample {

    // ★ throws IOException ← 「IOException が出るかも」と宣言している
    static void readFile(String path) throws IOException {
        BufferedReader reader = new BufferedReader(new FileReader(path));
        System.out.println(reader.readLine());
        reader.close();
    }

    // 呼び出し元が責任を持ってcatchする
    public static void main(String[] args) {
        try {
            readFile("data.txt");

        } catch (IOException e) {
            // チェック例外は必ずここでcatchしなければコンパイルエラーになる
            System.out.println("ファイルエラー: " + e.getMessage());
        }
    }
}
```

> 💡 **throws を書かないとコンパイルエラー**になります。チェック例外は「無視できない例外」なのです！
> 

| 例外の種類 | catchしなかった場合 |
| --- | --- |
| ② Exception系（チェック例外） | **throws宣言が必須**（書かないとコンパイルエラー） |
| ③ RuntimeException系（非チェック例外） | throws宣言は不要（書いても良い） |

## 💥 例外的状況を自分で発生させる（throw）

Javaでは **`throw`** を使って、自分でわざと例外を発生させることができます。
「おかしい値が来たら意図的にエラーにする」場面で使います。

```java
public class ThrowSample {

    // 年齢を設定するメソッド。マイナスはおかしいので例外を発生させる
    static void setAge(int age) {
        if (age < 0) {
            // throw で例外インスタンスを投げる（例外的状況を意図的に作る）
            throw new IllegalArgumentException("年齢はマイナスにできません: " + age);
        }
        System.out.println("年齢を設定しました: " + age);
    }

    public static void main(String[] args) {
        try {
            setAge(20);   // OK
            setAge(-5);   // ← ここで例外が発生！

        } catch (IllegalArgumentException e) {
            System.out.println("不正な値エラー: " + e.getMessage());
        }
    }
}
```

**実行結果**

```
年齢を設定しました: 20
不正な値エラー: 年齢はマイナスにできません: -5
```

> 💡 `throw`（投げる）と `throws`（宣言する）はスペルが似ていますが別物です！
> 

| キーワード | 意味 | 使う場所 |
| --- | --- | --- |
| `throw` | 例外を**発生させる** | メソッドの中（処理の中） |
| `throws` | 例外が**出るかもと宣言する** | メソッドの定義部分 |

## 🏗️ オリジナル例外クラスの定義

既存の例外クラスだけでは表現しきれない「アプリ独自のエラー」を作りたいときは、**自分で例外クラスを定義**できます。

### ① チェック例外として作る（Exception を継承）

```java
// オリジナル例外クラス：残高不足のエラー
class InsufficientBalanceException extends Exception {

    private int shortfall;  // 不足金額を持たせる

    // コンストラクタ
    public InsufficientBalanceException(int shortfall) {
        super("残高が不足しています。不足額: " + shortfall + "円");
        this.shortfall = shortfall;
    }

    public int getShortfall() {
        return shortfall;
    }
}
```

### ② 使ってみる

```java
public class OriginalExceptionSample {

    // 引き出し処理（残高が足りなければオリジナル例外を投げる）
    static void withdraw(int balance, int amount) throws InsufficientBalanceException {
        if (amount > balance) {
            int shortfall = amount - balance;
            throw new InsufficientBalanceException(shortfall);  // 自作例外を投げる！
        }
        System.out.println(amount + "円を引き出しました。残高: " + (balance - amount) + "円");
    }

    public static void main(String[] args) {
        try {
            withdraw(1000, 800);   // OK
            withdraw(1000, 1500);  // 残高不足 → オリジナル例外が発生！

        } catch (InsufficientBalanceException e) {
            // 自作例外インスタンスからオリジナル情報を取り出せる
            System.out.println("エラー: " + e.getMessage());
            System.out.println("不足額は " + e.getShortfall() + "円です");
        }
    }
}
```

**実行結果**

```
800円を引き出しました。残高: 200円
エラー: 残高が不足しています。不足額: 500円
不足額は 500円です
```

### オリジナル例外クラスの継承先の選び方

| 継承元 | 特徴 | 使いどころ |
| --- | --- | --- |
| `Exception` を継承 | チェック例外になる | 呼び出す側に必ず対処させたい重要なエラー |
| `RuntimeException` を継承 | 非チェック例外になる | プログラムのバグ・想定外の使い方を示すエラー |

> 💡 **チームや現場では独自の例外クラスを作ることが多い**です。エラーの種類に名前をつけることで、コードが読みやすく・デバッグしやすくなります！

## 🎯 全体のまとめ

```
エラーの種類
  ├── 文法エラー    → コンパイル時に発覚（IDE が教えてくれる）
  ├── 実行時エラー  → 例外処理（try-catch）で対応！ ← ここが今回のメイン
  └── 論理エラー    → テストや見直しで対応

例外クラスの系統
  ├── ① エラー系例外           → 対処しなくてよい
  ├── ② Exception系例外        → 必ずcatchが必要（チェック例外）
  └── ③ RuntimeException系例外 → NullPointerExceptionなど（非チェック例外）

例外処理の構文
  ├── try-catch          → 基本の書き方
  ├── finally            → 必ず実行したい後片付け
  └── try-with-resources → リソースの自動クローズ

例外の発生と伝播
  ├── 例外の伝播   → catchされなければ呼び出し元へどんどん伝わる
  ├── throws宣言   → チェック例外を伝播させるとき、メソッドに必須の宣言
  └── throw文      → 自分で意図的に例外的状況を発生させる

オリジナル例外クラス
  ├── Exception を継承      → チェック例外（対処を強制したいとき）
  └── RuntimeException を継承 → 非チェック例外（バグや不正操作を示すとき）
```

> ✅ **例外処理を使うと、プログラムが突然クラッシュするのを防ぎ、ユーザーに優しいエラーメッセージを出すことができます！**
✅ **オリジナル例外クラスを使えば、アプリ独自のエラーを分かりやすく表現でき、チーム開発でも読みやすいコードになります！**
>
