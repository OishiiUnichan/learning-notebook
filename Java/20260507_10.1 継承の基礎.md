# 10.1 継承の基礎

subject: Java

- 似通ったクラスの開発方法
1. コピペ解決法
    
    →もととなるクラスをコピーし、新規追加情報を追加していく方法
    
    【問題点】
    
    1. 追加・修正に手間を要する
        
        →コピー元のクラスに変更が生じた場合、コピー先のクラスにも変更を行う必要がある
        
    2. 把握や管理が難しくなる
        
        →コピー先のクラスの内容の大半は、コピー元のクラスと同じ。コピー先の追加情報の把握や管理が難しくなる
        
2. 継承
    
    →クラス宣言に「**extends**」キーワードを使用して、元となるクラスを拡張したクラスを作成することを宣言する。
    
    ```java
    public class クラス名 extends 元となるクラス名{
    	元となるクラスとの差分メンバ
    }
    ```
    
    ※**extends**：「クラス名」は「元となるクラス名」を拡張する、という英語が成立するように動詞にsをつける。
    
    ※extendsキーワードがクラス宣言についていると、JVMは元となるクラスのメンバをもっている、と判断してくれる。
    
    →プログラム実行時に、元となるクラスメンバが自動的に引き継がれているように見える動作が「継承」の由来となっている
    
    1. ［対になる］呼び方について
        
        継承元：スーパー、基底、親
        
        継承先：↑サブ、↑派生、子
        
        ※クラス図の継承関係を表現する矢印の向きに注意。『親』は産むまで『子』を認識できないが、子は産まれた時から親を知ることができる。
        
    2. 継承のバリエーション
        1. 継承先のクラスをさらに継承してクラスを作成することも可能
            
            呼び方）
            
            区別可能：親クラス←子クラス←孫クラス
            
            区別不可：スーパークラス←サブクラス←サブクラス
            
        2. 1つの継承先のクラスが複数の継承元のクラスをもつことは許されていない
            
            多重継承は技術的に可能（許されている言語もある）
            
            ややこしい問題が生じるため、javaでは許可していない（単一継承）
            
            →［例］
            
            複数の継承元のクラスで処理の異なる同じメソッドが存在した場合、どちらの処理を継承すべきかという問題が生じる
            
            親Ａ｛投げる（）｛豪速球｝｝
            
            子Ｃ｛投げる（）｛豪速球 or 変化球｝？｝
            
            親Ｂ｛投げる（）｛変化球｝｝
            
        3. オーバーライド
            
            →継承先のクラスで継承元のメソッドの処理内容を変更する機能
            
            ※オーバーロードとの違い
            
            オーバーロード：多重定義
            
            →load：読み込む
            
            オーバーライド：再定義
            
            →ride：乗る、またぐ
            
            再定義のため、メソッドの宣言は継承元のメソッド宣言と同じにする
            
            →変更は、**メソッドブロックの内容の記述になる**
            
            ★継承を用いて継承先のクラスに宣言されたメンバの扱い
            
            1. 継承元のクラスに同じメンバが「なければ」、そのメンバは「追加」になる
                
                ※オーバーライドしたつもりがメソッド名を間違うとオーバーライドにならず、継承先のクラスで新規追加されたメソッドとみなされるので注意
                
            2. 継承元のクラスに同じメンバが「あれば」、そのメンバが「優先」される
                
                ※override：～乗り越える、～より優位に立つ、～優先する、～無効にする、～を覆す
                
                ※overwrite：［～の］上に書く、［～に］上書きする
                
                ![image.png](10%20%E7%B6%99%E6%89%BF1/image.png)
                
        4. 継承やオーバーライドの禁止（模造品対策）
            
            →　final：最後の、最終の、決定的な、確定的な
            
            ［実例］**変数宣言にfinalをつける　→　定数扱い（再代入禁止）**
            
            - クラス宣言にfinalをつける→継承禁止
            - メソッド宣言にfinalをつける→オーバーライド禁止

- **`IncompatibleClassChangeError`**:
直訳すると「互換性のないクラス変更エラー」です。プログラムを実行しようとしたら、クラスの関係性がおかしくなっているときに出ます。
- **`class code10_07.SuperHero overrides final method`**:
「SuperHeroクラスが、**final**がついたメソッドをオーバーライドしています」という意味です。
- **`code10_07.Hero.slip()V`**:
原因となっているのは、`Hero`クラスにある `slip()` というメソッドです。（最後の `V` は「戻り値がvoidですよ」というJava内部のサインです）
