# インターフェース

- 継承階層を下ではなく、上にたどっていくと特に抽象度の高い抽象クラスになる。
    
    →抽象クラスではなく、インターフェースとして特別に定義することができる。
    
    （クラスではなく、新たにインターフェースとして扱う）
    

## ［インターフェースとして定義できる条件］

1. すべてのメソッドは抽象メソッドである。
    
    利便性が上がっただけで、条件が変更になったわけではない。
    
    ※Java8からメソッドを実装しなかった場合の規定の処理を定義できるようになった［p.415］
    
2. 基本的にフィールドは１つも持たない。
    
    →定数フィールドだけは宣言が許されている［p.415］
    

### ［書式］

```java
public interface インターフェース名{
	戻り値の型　抽象メソッド名();
}
```

### 抽象度の高い抽象クラス

［書式］

```java
public abstract class クラス名{
	public abstract 戻り値の型 抽象メソッド名();
	}
```

#### 使い分けについて

役割（目的）が根本的に違う。一番わかりやすい使い分けの基準は
「**それが何であるか（Is-a）**」か
「**何ができるか（Can-do）**」かです。

### 1. 抽象クラス： 「何であるか（Is-a）」の関係

抽象クラスは、「共通の性質や機能（中身）」を子クラスに引き継がせたいときに使います 。

**考え方**: 「子クラスたちは、結局この親クラスの『一種』だよね」というとき（例：勇者は『人間』の一種）。

- **できること**:
    - 具体的な処理（具象メソッド）を持てる。
    - 状態（フィールド変数）を持てる。
- **制約**: 1つのクラスは、1つの親クラスからしか継承できません（単一継承）。
    
    **例（飲み物）**:
    
    「コーヒー」も「お茶」も、どちらも「飲み物」という種類ですよね。
    
- **抽象クラス `Drink`**: 「名前」という変数や、「飲む」という具体的な共通処理を持たせます。

### 2. インターフェース： 「何ができるか（Can-do）」の関係

インターフェースは、「共通の振る舞い（ルール）」だけを約束させたいときに使います。

- **考え方**: 「全然違う種類のもの同士だけど、この『機能』だけは共通して持たせよう」というとき（例：勇者も、スマホも、目覚まし時計も『アラームを鳴らす機能』を持っている）。
- **できること**:
    - 原則として「メソッドの看板（名前と引数）」だけを定義する 。
    - 中身の処理や、個別の変数（状態）は持たせないのが基本。
    
    **メリット**:
    1つのクラスにいくつでもセット（実装）できます（多重実装） 。
    **例（お掃除機能）**:
    
    「人間」も「お掃除ロボット」も、種類は全く違いますが「掃除する」という機能は共通化できます。
    
- **インターフェース `Cleanable`**: 「掃除する()」というルールの看板だけを用意します。

### 使い分けの早見表

| **項目** | **抽象クラス (abstract class)** | **インターフェース (interface)** |
| --- | --- | --- |
| **役割** | 「**共通の材料（中身）**」を
引き継ぐ | 「**共通のルール（看板）**」を
守らせる |
| **関係性** | Is-a（〜は〜の一種である） | Can-do（〜ができる） |
| **処理の記述** | 書ける（具象メソッドOK） | 原則書けない
（抽象メソッドのみ） |
| **変数の保持** | 持てる（普通のフィールドOK） | 持てない（定数のみ） |
| **同時利用** | 1つだけしか継承できない | 何個でも同時に実装できる |

### 💡 考え方のヒント

もし迷ったら、「共通の変数（情報の箱）や、最初から完成させておきたい共通処理があるか？」を考えてみてください 。

- **YES**なら： **抽象クラス**。
- NO（ただ『このメソッドを作れ』と命令したいだけ）なら： **インターフェース**。
