# ［継承］

1. ［拡張］extends
    
    元となるクラスの内容を『拡張』したクラスを作成する。
    
    ［イメージ］親から能力（器と中身）を受け継ぐ
    
    ［書式］
    
    ```java
    public class クラス名 extends ［抽象］クラス名{
    	元となるクラスとの差分メンバ;
    }
    ```
    
2. ［実装］implements
    
    継承した抽象メソッドの内容を『実装』する。
    
    ［イメージ］神から才能（器）だけを与えられる（中身は自分で決める）
    
    ［書式］
    
    ```java
    public class クラス名 implements インターフェース名{
    	抽象メソッドの内容を確定する;
    }
    ```
    

#### ［インターフェースの効果］

1. 同じインターフェースを実装した複数のクラスに、『共通』のメソッド群をもたせることを強制できる
2. インターフェースを実装していれば、そのインターフェースで定義されたメソッドをもっていることが『保証』される

---

### 自動販売機に例えると…

「中身のパーツを受け継ぐ」のが**継承**、
「外側のボタンというルールを守る」のが**実装**（インターフェース）です。

### 1. ［継承］・［拡張］extends

**＝ 自販機の「中身の機械（ベースパーツ）」を受け継ぐ**

元となるクラスの「共通の材料（中身）」を引き継いで、さらに新しい機能を追加（拡張）すること

- **イメージ**: 親自販機から「冷却機能」や「コイン選別機」などの「能力（器と中身）」をそのまま受け継ぐ。
- **自販機の例**: 「普通の自販機」を継承して、「アイス専用自販機」を作る。
    - 基本の機械（冷やす、お金を数える）は親から貰い、自分は「アイスを押し出すアーム」という**差分メンバ**だけを追加すればOK。

**【書式】**

```java
public class アイス自販機 extends 自販機ベース {
    // 親から「冷やす機能」などは貰っているので、
    // ここには「アイス専用アーム」などの差分だけ書く
}
```

---

### 2. ［実装］implements

**＝ 自販機の「前面パネル（操作ボタン）」のルールを守る**

インターフェースで決められた「メソッドの看板」だけを受け取り、具体的な中身を自分で作る（確定させる）ことです 。

- **自販機の例**: 「ドリンク販売機能」というインターフェースを実装する。
    - 「ボタンを押したら商品が出る」というルールさえ守れば、中身がコーラだろうが、お茶だろうが自由です。

**【書式】**

```java
public class コーラ自販機 implements ドリンク販売機能 {
    // インターフェースで決まった「売る()」というメソッドの
    // 中身を「コーラを出す」という処理で確定させる
}
```

---

### 3. ［インターフェースの効果］

**＝ どの自販機も「同じボタン」がついているという保証**

インターフェースを使えば、全く違う種類のクラス（自販機、券売機、レジ）であっても、「共通のルール」を持たせることができます。

- **強制**: 「支払う()」というインターフェースをセットすれば、その自販機は必ず支払い機能を作らなければなりません（ノルマ）。
- **保証**: 利用者は、中身がどうあれ「このボタン（看板）があるなら、こう動くはずだ」と安心して操作できます。

---

### 💡 まとめ

- **extends（継承）**： 「自販機の一種」を作るために、**中の機械**を使い回す。
- **implements（実装）**： 「販売できる」という**ルール**を守るために、外側のボタンをセットする。
