memo: varでの型推論

```java
package code16_02_03;

import java.util.LinkedList;

public class Main {

	public static void main(String[] args) {
		// ① 左側を var に書き換え
		var names = new LinkedList<String>();

		names.add("湊");
		names.add("朝香");
		names.add("菅原");

		// ② イテレータも var でOK
		var it = names.iterator();
		while (it.hasNext()) {
			// ③ 取り出す変数も var にできます
			var n = it.next();
			System.out.println(n);
		}
	}
}
```

## `var` の解説

---

### varとは？

**Java 10から導入**された機能で、型をJavaが自動で推論してくれる書き方です。

```java
// 従来の書き方
LinkedList<String> names = new LinkedList<String>();

// varを使った書き方
var names = new LinkedList<String>();
// ↑ Javaが右辺を見て自動的にLinkedList<String>だと判断
```

---

### コードの3箇所を比較

**① リストの宣言**

```java
// 従来
LinkedList<String> names = new LinkedList<String>();

// var
var names = new LinkedList<String>();
// 右辺にLinkedList<String>と書いてあるので型推論できる
```

**② イテレータ**

```java
// 従来
Iterator<String> it = names.iterator();

// var
var it = names.iterator();
// namesがLinkedList<String>とわかってるので推論できる
```

**③ 取り出す変数**

```java
// 従来
String n = it.next();

// var
var n = it.next();
// itがIterator<String>とわかってるので推論できる
```

---

### varを使う条件

右辺から型が**明確にわかる場合のみ**使えます。

```java
var names = new LinkedList<String>(); // ✅ 右辺が明確
var x = 10;                           // ✅ int型と推論
var y;                                // ❌ 右辺がないので推論不可
var z = null;                         // ❌ nullだけでは型不明
```

---

### 前回のListとの違い

```java
// List型で受け取る（インターフェース型）
List<String> names = new LinkedList<String>();
// → 後で差し替えやすい・LinkedList専用メソッドは使えない

// varで受け取る
var names = new LinkedList<String>();
// → LinkedList<String>として推論される
// → LinkedList専用メソッドも使える！
```

---

### メリット・デメリット

|  | 内容 |
| --- | --- |
| ✅ メリット | コードが短くなる |
| ✅ メリット | 長い型名を省略できる |
| ❌ デメリット | 型が一目でわからないことがある |
| ❌ デメリット | 右辺がないと使えない |

---

### まとめ

```
var = 型推論　→　Javaが右辺を見て型を自動判断

従来  : LinkedList<String> names = new LinkedList<String>();
var   : var names = new LinkedList<String>();

条件  : 右辺から型が明確にわかること
導入  : Java 10以降
```

> `var` は書くのが楽になりますが、**型が何かわかりにくくなる**こともあるので、チームのルールや可読性を考えて使いましょう！
