# 7.2 オブジェクト指向の定義と効果

［概念］物事の大体の考え方を表現するときに使う［抽象的］

［定義］物事を限定するような考え方を表現するときに使う［具体的］

※ 概念を定義することは、人によって様々である（図7-4 P.261）！

定義の提唱）オブジェクト指向とは、ソフトウェアを開発するときに用いる「部品化」の考え方を指す。

- 手続き指向（（手順）における部品化）
    
    指示書を分割（クラスやメソッド）して、プログラムを作る手法［部品に分割する］
    	→ 部品課の客観的なルールはなく、主観的な判断に依る。
    
- オブジェクト指向（（役割）における部品化）
    
    作業過程を効率よく分割して、プログラムを作る手法［部品を用意する］
    	→ 効率よく作業するために、部品（道具）をつくる。
    

## ☆ オブジェクト指向のメリット

目的：開発者が内容を把握しやすいプログラム開発を実現すること！

→プログラミングする際の手間よりも開発後の作業に重点を置く！

［例］「万能」型のロボットに詳細かつ大量の指示を送るよりも、「専用」型のロボットを複数用意し、簡単な支で連携させる。

→※ どちらのタイプのロボットのほうが将来的に扱いやすいか？

- プログラムの変更を用意にしたい（柔軟性・保守晴雨の向上）
    
    → カプセル化 ［第13章］
    
- プログラムの一部を簡単に転用したい（再利用・拡張性の向上）
    
    → 継承［第10章、11章］
    　 多様性［第12章］
    

※ 上記の要望（メリット）を実感するためには、実際に数か月を要してプログラムを開発してみる必要がある！

→ 自主制作物（開発業務の疑似体験 ）は、就職活動の自己PR文に活用できる。
