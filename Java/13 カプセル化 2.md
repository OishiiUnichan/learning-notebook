# getter

単純にフィールドの値（名詞、データ）を取り出すだけのメソッド

［書式］

```java
public フィールド型　getフィールド名（）{　←フィールド名は大文字
	return this.フィールド名；
	}
```

※getter名）フィールドの型が『boolean型』の場合、接頭辞は『is』を採用

```java
public class User {
    private boolean admin; // 管理者かどうか（privateで隠す）

    // これがノートに書いてある「is」を使ったGetter！
    public boolean isAdmin() {
        return this.admin;
    }
}
```

# setter

単純にフィールドの値を設定（代入）するだけのメソッド

［書式］

```java
public フィールド型　setフィールド名（）{　←フィールド名は大文字
	this.フィールド名＝引数名；
	}
		thisは省略しない
```

※setter名）フィールドの型が『boolean』の場合、接頭辞に『is』を採用するとゲッターのオーバーロードになる。

［利用方法］

×　フィールドの呼び出しで直接値を代入するのではなく、

〇　セッターの呼び出しで、代入する値を実引数で指定する。

オーバーロードになるとは？

```java
public class User {
    private boolean active; // フィールド（中身）

    // １．Getter（ゲッター）
    // 引数がないので、シグネチャは「isActive()」
    public boolean isActive() {
        return this.active;
    }

    // ２．間違ったSetter（セッター）
    // 名前をisにしちゃうと、引数があるのでシグネチャは「isActive(boolean)」になる
    // １と名前が同じなので「オーバーロード」として成立してしまう
    public void isActive(boolean active) {
        this.active = active;
    }
}
```

［サンプルコード］

```java
public class Hero {
    private int hp; // 隠す

    // Getter（値を取り出す窓口）
    public int getHp() {
        return this.hp;
    }

    // Setter（値を代入する窓口）
    public void setHp(int hp) {
        this.hp = hp;
    }
}
```

```java
public class Main {
    public static void main(String[] args) {
        Hero h = new Hero();

        // 直接代入はNG（h.hp = 100 はエラー）
        h.setHp(100); // セッターで代入

        System.out.println("HPは" + h.getHp()); // ゲッターで取得
    }
}
```

#### ★setterのフィールド型は基本的に「void」

Javaの標準的なルール（JavaBeansという慣習）では、「**setterは値をセットするだけの仕事なので、何も返さない（void）**」とするのが超・定番の決まりきった形。

1. なぜ「原則void」なのか
setterの役割は、「外から来たデータをフィールドに詰め込むこと」そのものです。 「はい、入れました！」で仕事が完結するため、呼び出し元に何かを報告する（戻り値を返す）必要がないと考えられているからです。
2. 「void以外」にするのはどんな時？
プロの世界では、たまに void 以外を返すように設計することもあります。
    - 自分自身（this）を返す場合
        
        `public Hero setHp(int hp)` のように、自分自身を返すようにすると、`hero.setName("ミナト").setHp(100);` のように、メソッドを数珠つなぎ（メソッドチェーン）で書けるようになります。
        
    - 成功か失敗かを返す場合
        
        `public boolean setHp(int hp)` のようにして、「正しい値だったのでセットした（true）」「不正な値だったので拒否した（false）」と報告させることも技術的には可能です。
        

## ★getter、setter（併せてaccessor）の存在価値

1. 読み取り専用、書き込み専用のフィールドを実現できる。
    - 読み取り専用：getterのみ使用
    - 書き込み専用：setterのみ使用
2. クラスの内部設計を自由に変更できる
    
    将来、仕様変更する必要が生じた場合にもメソッドの処理として対応することができるため、クラス利用者に対応依頼する必要がない
    
3. フィールドへのアクセス検査ができる
    
    フィールドへの設定の妥当性を代入する前に、検査するコードの記述ができる（code13-13）
