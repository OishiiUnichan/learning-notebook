### メモリには２領域存在する

- スタック領域
    
    変数宣言すると、スタック領域にデータ格納する区画が確保される。
    
- ヒープ領域
    
    new演算子で展開される情報は、ヒープ領域で**管理**される。
    

※確保される区画サイズは、データ型による（整数型の場合はp.52参照）

- 基本型：値そのものは、スタック領域で管理
- 参照型：値そのものは、ヒープ領域で管理し、スタック領域ではその場所を管理（参照する）。

※配列変数の場合、要素数によってはスタック領域で確保した区画では管理できない可能性がある！　→　ヒープ領域の利用

### 結論：本体は1つ、リモコンが2つ

この状態は、**「1台のテレビ（実体）」に対して、「2つのリモコン（変数）」がある状態**と同じ。

- リモコンA (`arrayA`) でチャンネルを `1` にした。
- リモコンB (`arrayB`) を、リモコンAと同じテレビが動くように設定した。
- リモコンB (`arrayB`) でチャンネルを `100` に変えた。
- リモコンA (`arrayA`) で「今、何チャンネル？」と確認したら……当然 `100` 。

```java
package code04_15;

public class Main {
    public static void main(String[] args) {
        // 1. 配列の実体（[1, 2, 3]）がメモリの「A番地」に作られる
        //    arrayA には「A番地」という住所が代入される
        int[] arrayA = {1, 2, 3};

        // 2. 住所を書き込むための空のメモ用紙（変数）を用意する
        int[] arrayB;

        // 3. arrayA の持っている「A番地」という住所を、arrayB にコピーする
        //    ※中身の 1, 2, 3 がコピーされるわけではないのがポイント！
        arrayB = arrayA; 

        // 4. arrayB（A番地）の0番目を 100 に書き換える
        //    実体は1つしかないので、この時点で「A番地のデータ」自体が変わる
        arrayB[0] = 100;

        // 5. arrayA（A番地）の0番目を出力する
        //    参照先が同じ「A番地」なので、結果は 100 になる
        System.out.println(arrayA[0]);
    }
}
```

### どういうときに使うねん

#### 大きなデータの一部だけを一時的に担当させるとき

```java
// 映画100本のデータが入った巨大な配列
String[] movieDatabase = new String[100]; 

// 「今、編集中の映画」という名前（変数）を用意
String currentEditMovie;

// 50番目の映画を編集したい！
// movieDatabase[50] の「住所」を currentEditMovie に代入する
currentEditMovie = movieDatabase[50];
```

```java
// 巨大な配列（映画100本分）
String[] movies = {"七人の侍", "羅生門", "リング", ...};

// 判定ロジックを書くとき、いちいち「movies[50]」と書くのは面倒だし、
// 後で「やっぱり49番目だった」となった時に全部書き直すのは地獄です。
int index = 50; 

// ここで「あだ名（参照）」の登場！
String target = movies[index]; 

// 以降、targetという短いあだ名でロジックを書ける
if (target.equals("時代劇")) {
    // 処理...
}
```
