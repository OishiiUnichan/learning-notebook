# コンストラクタ

- newされた直後のオブジェクトのフィールドは初期化される。
    
    →基本型（数値型：０、boolean型：false）
    
    　参照型（配列型、クラス型：null）
    

※インスタンスとして利用する場合は、フィールドに適切な値を設定する必要がある。

→自動実行する機能（メソッドの一種）を**コンストラクタ**と呼ぶ

［書式］コンストラクタには戻り値の型は記述しない（void含）

```java
public クラス名(){ ←判断材料、（戻り値：無し、クラス名：使用）
	自動的に実行する処理;
}
```

※コンストラクタは直接呼び出せない

→オブジェクト生成直後に、JVMによって呼び出される

→開発者がプログラムで直接呼び出す手段は用意されていない

![image.png](9 さまざまなクラス機構 2/image.png)

※コンストラクタはメソッドの一種であるため、メソッドと同様の取り扱いができる場合もある

## 【類似点】

1. コンストラクタに「毎回異なる追加情報」を渡すには、引数を利用する。
    
    ※実引数は、new演算子を使用した際に指定する。
    
    →JVMによって自動的にコンストラクタが実行される際に、実引数が仮引数に渡される。
    
2. 引数が異なる同名コンストラクタを多重定義（オーバーロード）できる。
    
    →指定された実引数の構成と一致する、仮引数で構成されているコンストラクタが動作する
    

## 【相違点】

1. 暗黙のコンストラクタ
    
    インスタンスを生成する際、必ずコンストラクタを実行する仕様になっている。
    
    →1つ以上のコンストラクタを定義する必要がある。
    
    【特例】
    
    1つもコンストラクタが定義されていない場合に限りデフォルトコンストラクタが自動的に実行される仕組みになっている
    
    →デフォルトコンストラクタ：引数なし、処理なしのコンストラクタ
    
2. コンストラクタの呼び出し
    
    メソッドの呼び出し）〇 this.attack();
    
    コンストラクタの呼び出し）× this.Hero(”ダミー”);
    
    →コンストラクタを直接指定することはできないが、引数の指定で依頼することはできる
    
    〇 this(”ダミー”);
    
    ※ブロックの最初の行に記述する
    
    ※メソッドの呼び出しのthis：自分自身のインスタンス
    　コンストラクタの呼び出しのthis：同一クラスの別コンストラクタを指す
