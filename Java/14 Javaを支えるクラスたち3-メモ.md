## `toString()`のオーバーライドとは

まず、このコードで重要な**前提知識**から整理する。

---

### ① オーバーライドしないとどうなるか

`toString()`をオーバーライドしない場合、`Object`クラスのデフォルト実装が呼ばれる。

```java
Hero h = new Hero("ミナト");
System.out.println("Heroインスタンス：" + h.toString());

// 出力結果（オーバーライドなし）
// Heroインスタンス：code14_05.Hero@1b6d3586
```

これは**パッケージ名.クラス名@ハッシュ値**という形式で、人間には何の情報もわからない。

---

### ② だからオーバーライドが必要

`Hero`クラスで`toString()`を上書き（オーバーライド）することで、**好きな文字列を返せる。**

```java
@Override
public String toString() {
    return "名前：" + this.name + "／HP：" + this.hp;
}
```

```
// 出力結果（オーバーライドあり）
Heroインスタンス：名前：ミナト／HP：100
```

格段に読みやすくなった！

---

### ③ オーバーライドの仕組み

```
Object クラス
  └── toString()  → "code14_05.Hero@1b6d3586"  ← デフォルト

Hero クラス（Objectを継承）
  └── toString()  → "名前：ミナト／HP：100"     ← 上書き！
```

`@Override`アノテーションは**「親クラスのメソッドを上書きしますよ」** という宣言。書かなくても動くが、書くことでミスをコンパイラが検出してくれる。

---

### ④ `+`演算子でも自動的に呼ばれる

実は`toString()`は明示的に呼ばなくても、文字列結合の際に**自動で呼び出される。**

```java
// この2つは同じ意味
System.out.println("Hero：" + h.toString());
System.out.println("Hero：" + h);  // toStringが自動で呼ばれる
```

---

### まとめ

|  | 結果 |
| --- | --- |
| オーバーライドなし | `code14_05.Hero@1b6d3586`（意味不明） |
| オーバーライドあり | `名前：ミナト／HP：100`（わかりやすい） |

> **ポイント：** `Object`クラスの`toString()`はデフォルトではほぼ役に立たない文字列を返す。自分のクラスに合った内容を返すように**オーバーライドすることで、デバッグやログ出力が格段に見やすくなる。**
> 

---

### どうしてハッシュ値を返すのか

### ① なぜデフォルトはハッシュ値なのか

`Object`クラスはJava**すべてのクラスの親**である。つまり、どんなクラスが作られるか事前にわからない。

```java
// Objectクラスの設計者はこれらを知らない
class Hero   { String name; int hp; }
class Monster { String name; int attack; }
class Item   { String name; int price; }
```

「名前を出力すればいい」「HPも出したい」など、**クラスごとに適切な文字列表現は違う。** そのため、Objectクラスでは「とりあえず全クラス共通で使える情報」として、

```
パッケージ名.クラス名@メモリ上の識別番号（ハッシュ値）
↓
code14_05.Hero@1b6d3586
```

を返す仕様になっている。これは「**このオブジェクトがメモリのどこにいるか**」 を示す情報であり、すべてのオブジェクトに必ず存在する。

> つまりハッシュ値は「何も決められないからとりあえず返せる唯一の共通情報」という立場。
> 

---

### ② なぜオーバーライドで出力内容を変えられるのか

Javaのメソッド呼び出しは**「実際のインスタンスの型」を優先する**という仕組みになっている。

```java
// toString()が呼ばれたとき、Javaはこう探す
Hero h = new Hero("ミナト");
h.toString();
```

```
① まずHeroクラスにtoString()があるか探す
        ↓ あればそれを使う！
② なければ親クラス（Object）のtoString()を使う
```

つまりオーバーライドとは**「親のメソッドを子が乗っ取る」** 仕組みであり、同じ`toString()`という名前でも、**どのクラスのインスタンスかによって呼ばれる中身が変わる。**

```java
Object o1 = new Object();
o1.toString(); // → Object の toString()が動く

Object o2 = new Hero("ミナト");
o2.toString(); // → Hero の toString()が動く ← 乗っ取り成功！
```

| なぜハッシュ値？ | すべてのクラス共通で返せる唯一の情報だから |
| なぜオーバーライドで変えられる？ | Javaは「実際のインスタンスの型」を優先してメソッドを探すから |

> **ポイント：** Objectクラスは「全クラスの共通ルール」を定めた設計図。ハッシュ値はその苦肉の策。オーバーライドは「子クラスが親の仕様を自分用に書き換える」という継承の核心的な仕組み。
