# カプセル化の目的とメリット

「カプセル化」とは

1. データとメソッドを１つのオブジェクトにまとめ、
2. その内容を隠蔽するための概念
    
    →アクセス制御
    

※想定外に発生する不具合を未然に防ぐための仕組み

# メンバに対するアクセス制御（フィールド＋メソッド）

|  | 名称レベル | アクセス修飾子 | イメージ | アクセス許可範囲 | 例 |
| --- | --- | --- | --- | --- | --- |
| 厳 | private | private | 自分専用 | 自身のクラス内 | private void check |
|  | package private | 何も書かない | 同じ家の人限定 | 同じパッケージ内 | void check |
|  | protected | protected | 親戚までOK | 継承
無：package privateと同じ
有：publicと同じ | protected check |
| 緩 | public | public | 誰でもウェルカム | パッケージが異なっていてもOK | public void check |

［書式］

アクセス修飾子　フィールド宣言；

アクセス修飾子　メソッド宣言｛・・・｝

## ★アクセス修飾子の定石

- フィールド）原則すべてプラべ→微調整
- メソッド）原則すべてパブリック→微調整

フィールド＝名詞、値が入ってる、データなので→プラべ

メソッド＝動詞、動きがついてる、（）で命令→パブリック

# クラスに対するアクセス制御

|  | 名称レベル | アクセス修飾子 | イメージ | アクセス許可範囲 | 例 |
| --- | --- | --- | --- | --- | --- |
| 厳 | package private | 何も書かない | 同じ家の人限定 | 同じパッケージ内 | void check |
| 緩 | public | public | 誰でもウェルカム | パッケージが異なっていてもOK | public void check |

※非publicクラスの中にpublic指定されたメンバ（フィールド＋メソッド）があったとしても、別パッケージのクラスからはそのメンバにアクセスすることはできない

→クラスに対するアクセス修飾の定石：一般的には「public」で修飾する

★非publicクラスの特徴

1. ファイル名はクラス名以外でもOK
2. 1つのファイルに複数のクラスの宣言ができる

［例］

１つのファイルに、

①１つのpublicクラス　ファイル名　〇

②１つのpublicクラスと複数の非publicクラス　ファイル名　△

③複数の非publicクラス　ファイル名：任意　？

④複数のpublicクラス　×
