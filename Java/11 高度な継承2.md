# 高度な継承に関する2つの不都合

- クラスの基本形で継承元のクラスを作成した場合、２つの不都合が生じる
    
    →設計に基づき、メンバを定義［８章］
    
    →必要に応じてコンストラクタを定義［９章］
    
    →メンバに対してカプセル化［１３章］
    

A. 不都合その１

- 継承先のクラスに必須のメソッドは継承元のクラスでも定義しておきたい
- 継承先のクラスで処理内容が異なる場合『詳細未定』のメソッドになる

［２つの心配事］

1. 継承先クラスでオーバーライドを忘れる可能性
    
    →オーバーライドを忘れていなくても、入力ミスによる新規追加メソッドになる可能性もある（ex.attack→atckなど）
    
2. 将来の開発者が『詳細未定』のメソッドを見た際に、以下判断がつかない
    - 将来処理を記述する必要のあるメソッドか
    - 処理内容が確定困難なメソッドゆえ、何もしなくて正解なのか

↑　継承先クラスを作成する視点（extendsによるクラスの利用）

---

↓　インスタンスを作成する視点（newによるクラスの利用）

［もう１つの心配事］

1. 『詳細未定』のメソッドがあっても、インスタンス化はできてしまう
    
    →現実世界と同様、未完成の設計から実体を生み出すと事故につながる
    

B. 不都合その2

→クラスには２つの利用方法があり、開発者はそれを自由に選ぶことができる
