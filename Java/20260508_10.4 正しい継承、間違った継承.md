# 正しい継承、間違った継承

### 1. is-aの関係［利用する観点］

正しい継承とは・・・

〇　継承元と継承先の両クラス間で下記の概念的な関係が成立する継承のこと

［関係］継承先のクラスは、継承元のクラスの一種である

※is-aの関係：正しい関係か否か

```java
〇正しい継承／is-aの関係

例：Drink（飲み物） ⇐ Coffee（コーヒー）
判定: コーヒーは飲み物の一種である。（正しい！）

// 正しい例：共通の性質（名前、飲む機能）を引き継ぐ
class Drink {
    String name;
    void gulp() { System.out.println(name + "をゴクリと飲んだ"); }
}

class Coffee extends Drink {
    // コーヒーは飲み物の一種なので、gulp()ができても違和感がない
    int caffeine;
}
```

　has-aの関係：別インスタンスをフィールドに利用する関係［p.323］

```java
〇正しい継承／has-aの関係
例：Pot has a Drink（ポットは、飲み物を持っている）

class Pot {
    String potName;
    // 継承せず、中身としてDrinkクラスを「持つ」
    Drink content; 

    void pour() {
        System.out.println(potName + "から" + content.name + "を注ぎます");
    }
}
```

×　間違った継承とは・・・

用意したメンバがあるからといって、is-aの関係を考えずに利用する継承のこと

```java
×間違った継承
例：Drink（飲み物） ⇐ Pot（ポット）
判定: ポットは飲み物の一種である……？（いいえ、違います！）

// 間違った例：名前（name）があるからといって継承してしまう
class Pot extends Drink {
    // ポットは「飲み物」ではないので、親から引き継いだ gulp()（飲む）
    // という命令が実行できてしまうのは、設計として非常に不自然。
}
```

## ★間違った継承を行わない理由（正しい継承を行う理由）

1. 継承元のクラスを変更した場合、継承先のクラスに存在するが、使用できないメンバが継承される可能性がある（論理エラーの懸念）
    
    現実世界を模した形式でプログラミングすることは、コンピュータのためではなく、あくまでもプログラムを開発する「開発者」のため（ボトルネック［p.257］）
    
    オブジェクト指向プログラミングとは、プログラマがソースコードを理解しやすく、拡張しやすくするための手法。

### 2.汎化・特化の関係［準備する観点：継承関係（継承ツリー）］

→ 正しい継承の意義

［継承元］

- 「抽象的であいまい」なクラスになる　→　汎化（一般化）
    
    →メンバを定めることが難しくなり、メンバの数は減る。
    
    ※共通事項の洗い出し
    

［継承先］

- 「特殊で具体的なクラスになる」　→　特化（具体化）
    
    →メンバを詳細に定めることができ、メンバの数は増える。
    
    ※個性事項の洗い出し

    2. ［用意する観点（継承元のクラスを利用する立場）］［１１章］、［１２章］
