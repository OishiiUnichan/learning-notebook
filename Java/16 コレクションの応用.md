# ★hashCode()メソッドについて

→インスタンスのハッシュ値を返すメソッド

→インスタンスの内容を一定のルールに従って数値化したデータ

→同じ内容のインスタンスは、同じハッシュ値になる！

ただし、同じハッシュ値でも、同じ内容のインスタンスとは限らない

［例］同じ６でも、5+1、4+2、3+3と、異なる内訳が考えられる

## 【hashCode()メソッドの必要性】

コレクションクラスにおいて、equals()メソッドによる等価判定は要素数によって計算の負荷を要する可能性がある。

［例］セット（集合）：青、黄、赤　←要素数：３

　　　↑ここに「赤」を追加したい

※要素数が多いほど、比較対象が多くなる

# 💡そこで！

HashMapやHashSetなど、ハッシュ系のコレクションクラスでは、下記の仕様になっている。

1. 最初にハッシュ値でインスタンスを比較する（==演算子で判定）
2. ハッシュ値が等しい場合に限り、equals()メソッドで判定を行う
    
    ※ハッシュ値が同じでもまれに同じ内容ではない場合もあるので、equals()で厳密に確認する仕様になっている。
    

なお、ObjectクラスのhashCode()メソッドはインスタンスが異なれば、異なるハッシュ値を返す仕様になっている。

そのため、コレクションクラスの仕様通りの動作を実現するためには、hashCode()メソッドをオーバーライドしてハッシュ値を正しく返す必要がある。

---

ノートの内容をざっくりまとめると、「重たい equals()（顔認証）を毎回やるのは大変だから、まずは軽い hashCode()（指紋チェック）で一次審査をして効率を上げよう！」という仕組みのことです。

具体的なコードと流れを簡潔に解説しますね。

### 二段構えの審査コード

```java
import java.util.Objects;

public class Hero {
    private String name;
    private int hp;

    // ★ 一次審査用の「指紋」を作る
    @Override
    public int hashCode() {
        // 中身が同じなら同じ数値を返す
        return Objects.hash(this.name, this.hp);
    }

    // ★ 二次審査（最終確認）
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj instanceof Hero h) {
            // 名前とHPが本当に一致するか厳密にチェック
            return this.name.equals(h.name) && this.hp == h.hp;
        }
        return false;
    }
}
```

### コンピュータの中での動き

`HashSet` などにデータを追加するとき、Javaは裏側でこう動いています。

1. **【一次審査】 hashCode() でチェック**
    - まずはハッシュ値を計算して、既存のデータと比べます。
    - **ハッシュ値が違えば：** その時点で「別人」と確定！ `equals` を呼ばずに一瞬で終わるので**爆速**です。
2. **【二次審査】 equals() でチェック**
    - ハッシュ値が被ったとき（まれにある）だけ、「中身も本当におなじ？」と `equals` で精密検査をします。

### なぜオーバーライドが必要なの？

デフォルトの `hashCode()` は、中身が同じでも「インスタンスが生まれた場所（メモリの住所）」で数値を作ってしまいます。

これだと、同じ「ミナト」さんを2人作ったときにハッシュ値がバラバラになり、一次審査で「別人」扱いされて重複登録できてしまいます。

だから、「中身（名前やHP）が同じなら同じハッシュ値を返す」ように書き換えて、正しく一次審査が通るようにしてあげる必要があるんです。
