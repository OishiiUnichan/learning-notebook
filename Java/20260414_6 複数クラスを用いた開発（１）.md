# ソースファイルを分割する

プログラム　ーーー　文書

パッケージ　ーーー　書棚

クラス　　　ーーー　タイトル

メソッド　　ーーー　章（見出し）

関連ある内容でまとめることを「部品化」という。

→　クラスやメソッド単位でまとめることを指す。

### クラス

複数のメソッドをまとめ、それを１つの単位として呼び出せるように名前をつけた部品のこと。

文書で例えると、関連ある見出し（章）をまとめてタイトルをつける作業に相当する。

#### クラスごとに部品化するメリット

1. 内容が整理されて管理しやすくなる。
2. ファイルごとに開発可能となり、分業しやすくなる。

# パッケージを利用する

- 物理的な管理）複数のフォルダの入れ子構造
    
    パッケージA
    
    ｜ーパッケージB　ー　javaファイルB
    
    ｜ーパッケージC　ー　javaファイルC
    
    例
    
    `java.util.Random().nextInt(数値)`
    
    →　javaのパッケージ内に、utilパッケージがあり、utilの中にRandomクラスがある
    
- 論理的な管理）１つのパッケージとみなすため、親子関係や階層関係はない
    
    パッケージA.パッケージB　ー　javaファイルB
    
    パッケージA.パッケージC　ー　javaファイルC
    
    例
    
    `java.util.Random().nextInt(数値)`
    
    →　java.utilパッケージ内に、Randomクラスがある
    
    ※　各ファイルは、お互いに独立した１つのパッケージに所属しているとみなす
    

# メソッドの呼び出し方法に注意

パッケージが異なれば、パッケージから指定して呼び出す必要がある。

［書式 ]

**`『パッケージ名.クラス名』.メソッド名（引数リスト）；`**

完全限定クラス名、完全修飾クラス名、FQCN

### import文の利用

1.コード6-8

クラスがどのパッケージに所属しているかをあらかじめ宣言することで、パッケージ名を省略して、メソッドの呼び出しができるようになる。

#### 記述場所

パッケージ宣言の『後』、クラス宣言の『前』

［書式 ]

`import パッケージ名.クラス名；←完全限定クラス名`

#### 注意

メソッドの呼び出しで、クラス名までは省略できない。

→クラスの所属するパッケージ名が参照できなくなるため、省略できる個所はパッケージ名のみ。

2.コード6-9

パッケージに所属するすべてのクラスをインポートする場合、クラス名の指定個所に＊の使用可。ただし、活用する場面はimport文の記述量が増えてしまう場合に限る。
横着するための活用は、クラスの所属が不明瞭になるため**非推奨。**

　tips!　

Eclipseの規定では、import文が99以上にならないと有効にならない設定になっている。
