## STEP 2｜DBの新規作成

```sql
-- DB作成（9章で学習）
-- 照合順序：日本語対応・大文字小文字を区別しない設定
```

## STEP 3｜テーブルの作成

今回は **商品テーブル（shohin）** と **カテゴリテーブル（category）** の2つを作成する。

### 3-1｜カテゴリテーブルの作成

```sql
-- category テーブル作成（9章で学習）
CREATE TABLE category (
  id_cat   INT          NOT NULL AUTO_INCREMENT,
  catname  VARCHAR(50)  NOT NULL,
  PRIMARY KEY (id_cat)
);
```

### 3-2｜商品テーブルの作成

```sql
-- shohin テーブル作成（9章で学習）
CREATE TABLE shohin (
  id_sho   INT           NOT NULL AUTO_INCREMENT,
  name     VARCHAR(100)  NOT NULL,
  price    INT           NOT NULL,
  stock    INT           NOT NULL DEFAULT 0,
  id_cat   INT           NOT NULL,
  PRIMARY KEY (id_sho)
);
```

**テーブルが作成されたか確認**

```sql
-- テーブル一覧の確認
SHOW TABLES;

-- カラム構成の確認（10章で学習）
SHOW COLUMNS FROM category;
SHOW COLUMNS FROM shohin;
```

> 💡 **設計のポイント（9章）**  
> - `AUTO_INCREMENT`：INSERT時にIDを自動採番  
> - `NOT NULL`：値の入力を必須にする制約  
> - `DEFAULT 0`：値未入力時の初期値を設定  
> - `PRIMARY KEY`：レコードを一意に特定するための主キー

## STEP 5｜SELECT文の練習

### 5-1｜基本的な絞り込みと並び替え

```sql
-- 価格が500円以上の商品（3章：WHERE句）
SELECT * FROM shohin WHERE price >= 500;

-- 価格の高い順に並べ替え（7章：ORDER BY）
SELECT * FROM shohin ORDER BY price DESC;

-- 価格が安い上位3件（7章：LIMIT）
SELECT * FROM shohin ORDER BY price ASC LIMIT 3;

-- 重複を除いてカテゴリIDの一覧（7章：DISTINCT）
SELECT DISTINCT id_cat FROM shohin;
```

### 5-2｜集計（7章：集約関数・GROUP BY・HAVING）

```sql
-- 全商品の平均価格
SELECT AVG(price) AS 平均価格 FROM shohin;

-- カテゴリ別の商品数と合計在庫数
SELECT id_cat, COUNT(*) AS 商品数, SUM(stock) AS 合計在庫
FROM shohin
GROUP BY id_cat;

-- 合計在庫が100以上のカテゴリのみ
SELECT id_cat, SUM(stock) AS 合計在庫
FROM shohin
GROUP BY id_cat
HAVING 合計在庫 >= 100;
```

### 5-3｜テーブル結合（8章：INNER JOIN）

```sql
-- 商品テーブルとカテゴリテーブルを結合
SELECT shohin.name, shohin.price, category.catname
FROM shohin
INNER JOIN category
ON shohin.id_cat = category.id_cat;

-- 価格の高い順に並べ替えて結合
SELECT shohin.name, shohin.price, category.catname
FROM shohin
INNER JOIN category
ON shohin.id_cat = category.id_cat
ORDER BY shohin.price DESC;
```

### 5-4｜サブクエリ（8章）

```sql
-- 平均価格より高い商品を抽出
SELECT * FROM shohin
WHERE price > (SELECT AVG(price) FROM shohin);
```

## STEP 6｜データの更新と削除

```sql
-- 【更新前に対象を確認する習慣をつける】（3章）

-- 更新対象の確認
SELECT * FROM shohin WHERE name = 'りんご';

-- 価格を更新（3章：UPDATE）
UPDATE shohin
SET price = 180
WHERE name = 'りんご';

-- 更新後の確認
SELECT * FROM shohin WHERE name = 'りんご';

---

-- 削除対象の確認（3章：DELETE前の必須確認）
SELECT * FROM shohin WHERE stock = 0;

-- 在庫が0の商品を削除
DELETE FROM shohin WHERE stock = 0;
```

> ⚠️ **重要：WHERE句は必ず付ける！**  
> `UPDATE` や `DELETE` で WHERE句を省略すると、全レコードが対象になる。  
> 必ず先に `SELECT` で対象を確認してから実行すること。

## STEP 8｜トランザクション（11章）

在庫の出庫処理をトランザクションで実装する。

```sql
-- 処理前の在庫確認
SELECT * FROM shohin WHERE id_sho = 1;

-- トランザクション開始（11章）
START TRANSACTION;

-- 在庫を減らす（出庫処理）
UPDATE shohin SET stock = stock - 10 WHERE id_sho = 1;

-- 処理途中の確認（まだコミットされていない状態）
SELECT * FROM shohin WHERE id_sho = 1;

-- ① 処理に問題があった場合 → ロールバック（取り消し）
ROLLBACK;

-- ロールバック後の確認（元に戻っているはず）
SELECT * FROM shohin WHERE id_sho = 1;

---

-- 再度トランザクション開始
START TRANSACTION;

UPDATE shohin SET stock = stock - 10 WHERE id_sho = 1;

-- ② 処理に問題がない場合 → コミット（確定）
COMMIT;

-- コミット後の確認（在庫が減っているはず）
SELECT * FROM shohin WHERE id_sho = 1;
```

> 💡 **トランザクションのポイント（11章）**  
> - `START TRANSACTION` → `COMMIT` で処理確定  
> - `START TRANSACTION` → `ROLLBACK` で処理取り消し  
> - DML（INSERT/UPDATE/DELETE）が対象。DDL（CREATE/DROP）は対象外

## STEP 9｜トリガーの作成と活用（12章）

テーブルへの更新処理（INSERT・UPDATE・DELETE）を **契機（トリガー）** にして、自動的に別テーブルも更新する仕組み。

### 9-1｜トリガーの登録

> 💡 **DELIMITERとは？**  
> 通常、MySQLは `;` をSQL文の区切りとして認識する。  
> トリガーの中にも `;` が含まれるため、そのままでは途中で文が終わったと誤認される。  
> `DELIMITER //` で区切り文字を `//` に変更し、`END //` まで1つの文として扱えるようにする。  
> コマンドラインでは記述が必要（phpMyAdminでは不要）。

```sql
-- 【トリガー作成前の確認】
SELECT * FROM shohin;

-- トリガーの登録（12章：CREATE TRIGGER）
-- 「shohinテーブルからDELETEされたとき、削除したレコードのid_catをログとして残す」イメージ
-- ※今回はシンプルに「category削除時に、対象カテゴリの商品在庫を0にする」トリガーを作成
DELIMITER //
CREATE TRIGGER category_delete_trigger AFTER DELETE
ON category FOR EACH ROW
BEGIN
  UPDATE shohin SET stock = 0 WHERE id_cat = OLD.id_cat;
END //
DELIMITER ;
```

**構文の解説**

| キーワード | 内容 |
|-----------|------|
| `AFTER DELETE` | DELETEの実行後にトリガーを発生させる |
| `BEFORE` | 実行前に発動（今回は `AFTER`） |
| `FOR EACH ROW` | レコード単位でトリガーを発生させる（必須の決まり文句） |
| `OLD.カラム名` | 削除・更新前のレコードの値を参照する |
| `NEW.カラム名` | 挿入・更新後のレコードの値を参照する（INSERT/UPDATEで使用）|

### 9-2｜動作確認・トリガーの確認と削除

```sql
-- トリガーの確認
SHOW CREATE TRIGGER category_delete_trigger;

-- 動作確認：カテゴリを削除してトリガーが発動するか見る

-- 削除前の在庫確認（id_cat=1 の商品）
SELECT * FROM shohin WHERE id_cat = 1;

-- カテゴリ（id_cat=1）を削除
DELETE FROM category WHERE id_cat = 1;

-- トリガー発動後の確認（id_cat=1 の商品の在庫が0になっているはず）
SELECT * FROM shohin WHERE id_cat = 1;

-- トリガーの削除（12章：DROP TRIGGER）
DROP TRIGGER category_delete_trigger;
```

> ⚠️ **注意点**  
> - トリガーはDDL（データ定義言語）であり、トランザクションの対象外。  
> - 自動で動作するため、意図しない更新が発生しないよう設計時に十分注意する。  
> - `OLD` は DELETE・UPDATE で使用可。`NEW` は INSERT・UPDATE で使用可。
